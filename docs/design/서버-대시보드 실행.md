# 서버-대시보드 실행

이 문서는 같은 PC에서 실행하는 C TCP 명령 서버, Gazebo, C 영상 중계기, Windows D 대시보드의 실행 절차를 모았습니다. 각 프로세스는 별도 터미널에서 실행합니다.

> 현재 C 명령 서버는 `127.0.0.1:47090`에 바인딩하므로 이 절차는 Windows 대시보드와 WSL이 같은 PC에 있는 경우 기준입니다. 다른 PC에서 접속하려면 서버 바인딩·방화벽·주소 설정을 별도로 맞춰야 합니다.

## 1. TCP 서버 실행

새 WSL 터미널에서 실행합니다.

```bash
source /opt/ros/jazzy/setup.bash
cd ~/EyetoArm/robot_ws/src/robot_server_package
python3 -m robot_server_package.tcp_server
```

서버가 시작되면 다음과 같은 로그가 나옵니다.

```text
TCP server listening at [('127.0.0.1', 47090)]
```

D 대시보드가 접속하면 `Initial GET_STATUS` 로그가 추가되고, 준비 상태와 보류 사유가 표시됩니다. Gazebo·MoveIt 실행 여부에 따라 `robot_ready=false`일 수 있으며, 이는 TCP 연결 실패와는 다릅니다.

## 2. Gazebo 실행 및 카메라 토픽 확인

영상 중계는 Gazebo 카메라 토픽을 구독하므로 먼저 시뮬레이션을 실행합니다. 모든 WSL 터미널에서 Gazebo와 같은 `ROS_DOMAIN_ID`를 사용하세요. 현재 환경에서 도메인 ID를 확인하려면:

```bash
echo "ROS_DOMAIN_ID=${ROS_DOMAIN_ID:-0}"
```

Gazebo가 실행 중이 아니면 WSL 터미널에서 실행합니다.

```bash
cd ~/EyetoArm
source /opt/ros/jazzy/setup.bash
source robot_ws/install/setup.bash
ros2 launch scripts/sim_sort_cell.launch.py gui:=false
```

별도 WSL 터미널에서 카메라 토픽이 있는지 확인합니다.

```bash
source /opt/ros/jazzy/setup.bash
source ~/EyetoArm/robot_ws/install/setup.bash
ros2 topic list | grep -E '^/(link_cam/image|gripper_cam/image|overview_cam/image)$'
```

다음 세 토픽이 보여야 합니다: `/link_cam/image`, `/gripper_cam/image`, `/overview_cam/image`.

## 3. 영상 송수신 실행

Gazebo 카메라 토픽이 확인된 뒤, 새 WSL 터미널에서 영상 중계기를 실행합니다. 처음 실행하거나 패키지 entry point가 설치되지 않았으면 한 번 빌드합니다.

```bash
cd ~/EyetoArm/robot_ws
source /opt/ros/jazzy/setup.bash
colcon build --packages-select robot_server_package
source install/setup.bash
```

그 다음 저장소 루트에서 중계기를 실행합니다.

```bash
cd ~/EyetoArm
source /opt/ros/jazzy/setup.bash
source robot_ws/install/setup.bash
ros2 run robot_server_package display_relay
```

중계기는 기본으로 `0.0.0.0:47092`에서 D의 접속을 기다립니다. 초당 FPS 로그에서 채널별 수신·송신을 확인할 수 있습니다.

```text
[C video FPS] link:rx=...,tx=... gripper:rx=...,tx=... fixed:rx=...,tx=...
```

- `rx`: Gazebo ROS 영상 토픽에서 C가 받은 FPS
- `tx`: JPEG 인코딩 후 TCP로 D에 보낸 FPS

`tx`는 소켓 전송 성공 기준이며, D의 JPEG 디코딩·화면 표시 FPS와 다를 수 있습니다. 영상은 명령·상태 TCP `47090`과 별도인 `47092`로 전송됩니다.

## 4. Windows 대시보드 실행

PowerShell에서 프로젝트의 Windows 대시보드 폴더로 이동합니다.(대시보드 폴더 위치 확인) 가상환경과 의존성 설치가 되어 있어야 합니다.

```powershell
cd C:\EyetoArm\dashboard-client
.\.venv\Scripts\Activate.ps1
$env:PYTHONPATH = (Resolve-Path .\src).Path
python -m eyetoarm.gui.window --host 127.0.0.1 --port 47090 --view relay --view-host 127.0.0.1 --view-port 47092
```

대시보드에서 C의 준비 상태와 보류 사유를 확인하고, 영상 영역에 링크·그리퍼·고정 카메라 화면이 표시되는지 봅니다. 대시보드가 먼저 실행되어 영상 서버에 접속하지 못했어도 중계기는 자동 재접속을 시도합니다.

## PS. 볼트 잡기 데모 실행

Gazebo와 로봇 제어기가 실행 중이고 벨트 이동 제어기는 정지한 상태에서, 새 WSL 터미널에서 실행합니다. Gazebo와 같은 `ROS_DOMAIN_ID`를 사용해야 합니다.

```bash
cd ~/EyetoArm
source /opt/ros/jazzy/setup.bash
source robot_ws/install/setup.bash
python3 scripts/pick_bolt_demo.py --part part_01
```

`part_01`은 M6×40 볼트입니다. 데모는 현재 볼트 위치를 읽어 접근·파지·들기·같은 위치에 내려놓기·팔 복귀를 수행합니다. Gazebo 시뮬레이션 전용이며 MoveIt 충돌 검사는 사용하지 않으므로, 실제 로봇에는 실행하지 마세요.

## 종료

각 프로세스의 터미널에서 `Ctrl+C`를 누릅니다. 대시보드 종료는 C 서버 프로세스를 종료하지 않습니다.
