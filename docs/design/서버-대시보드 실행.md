# 서버-대시보드 실행

이 문서는 같은 PC에서 C 서버와 Gazebo를 실행하고, Windows 대시보드에서 접속하는 방법을 설명합니다. 통합 launch 방식과 Ubuntu 터미널에서 개별 실행하는 방식 중 하나를 선택하세요. 두 방식을 동시에 실행하면 포트가 겹칠 수 있습니다.

## 1. 기존 통합 launch 파일로 실행

WSL Ubuntu 터미널에서 ROS Jazzy와 EyetoArm robot_ws 환경을 먼저 불러온 뒤, 저장소 루트에서 c_stack.launch.py를 실행합니다. 이 launch는 Gazebo GUI를 끄고 A 실시간 검출을 켜며 MoveIt은 끕니다. Windows 대시보드는 별도로 실행하므로 2번을 따르세요.

~~~bash
cd ~/EyetoArm
source /opt/ros/jazzy/setup.bash
source ~/EyetoArm/robot_ws/install/setup.bash
ros2 launch scripts/c_stack.launch.py
~~~

필요에 따라 true, false / 가제보GUI, Detect, Center, 무브잇실행, 무브잇GUI

ros2 launch scripts/c_stack.launch.py gui:=false start_a:=true start_b:=true start_moveit:=true moveit_gui:=false

실행 로그에서 TCP 서버, Gazebo, 영상 중계기와 A 검출 파이프라인이 시작되는지 확인합니다. B center 영상은 B 발행기가 별도로 실행 중이어야 수신됩니다.

launch를 종료할 때는 실행 중인 터미널에서 Ctrl+C를 누릅니다.

### 실행 방식 run_mode (단일·여러 실행)

같은 `ROS_DOMAIN_ID`·`GZ_PARTITION`에 이전 실행에서 남은 Gazebo·노드가 있으면 새 실행과 섞여 `joint_trajectory_controller` 오류, 시각 혼선, A 검출 중단, center 영상 없음이 생깁니다. launch 프로세스에만 종료 신호가 가는 경우(`kill`, 터미널 창 닫기)에 Gazebo가 남기 쉽습니다. `c_stack.launch.py`는 이를 `run_mode` 인자로 처리합니다.

| 값 | 동작 |
|---|---|
| `single`(기본) | 시작 전에 같은 도메인·파티션의 남은 Gazebo·노드를 정리(SIGINT → 10초 → SIGTERM → 5초 → SIGKILL)한 뒤 실행합니다. 기본 포트(47090·47092·47093)를 다른 프로세스가 쓰고 있으면 그 프로세스는 끄지 않고 시작을 거부합니다. 다른 도메인·파티션의 실행은 건드리지 않습니다 |
| `multi` | 남은 Gazebo가 있어도 경고만 출력하고 실행합니다. 여러 실행을 일부러 함께 띄울 때 씁니다 |

~~~bash
ros2 launch scripts/c_stack.launch.py auto_sort:=true                  # 단일 실행(기본)
ros2 launch scripts/c_stack.launch.py auto_sort:=true run_mode:=multi  # 여러 실행
~~~

- 끌 때는 Ctrl+C·`kill`·터미널 창 닫기 어느 방법이든 이 실행이 띄운 프로세스만 정리합니다. 처리 기록은 `logs/c_stack_guard_<시각>.log`에 남습니다.
- 시작이 거부되면 화면에 나온 PID·포트를 확인합니다. 기본 포트를 쓰는 프로세스가 다른 사람의 실행이면 그 실행이 끝난 뒤 다시 시작합니다.
- 이 처리는 `c_stack.launch.py`에만 있습니다. `sim_sort_cell.launch.py`·`dashboard_up.sh`로 띄운 뒤에는 `pgrep -af "gz sim"`으로 남은 Gazebo가 없는지 확인하고, 남아 있으면 정리합니다.

~~~bash
pgrep -af "gz sim"                      # 남은 Gazebo 확인(실행 중이면 셸·서버 2줄)
kill <PID>; sleep 10; kill -9 <PID>     # 안 꺼지면 -9로 강제 종료
~~~

### D 대시보드 없이 자동 분류 실행

첫 번째 WSL 터미널에서 위의 기본 launch 명령 대신 다음 명령으로 실행합니다.

~~~bash
cd ~/EyetoArm
source /opt/ros/jazzy/setup.bash
source robot_ws/install/setup.bash
ros2 launch scripts/c_stack.launch.py auto_sort:=true
~~~

두 번째 WSL 터미널에서 분류를 시작합니다. 시작 요청을 보내면 벨트가 움직이고 부품 자동 공급과 볼트 분류가 시작됩니다.

~~~bash
source /opt/ros/jazzy/setup.bash
source ~/EyetoArm/robot_ws/install/setup.bash
ros2 service call /c_sort_goal_receiver/start_run std_srvs/srv/Trigger '{}'
~~~

같은 터미널에서 정지를 요청합니다.

~~~bash
ros2 service call /c_sort_goal_receiver/stop_run std_srvs/srv/Trigger '{}'
~~~

## 2. Windows 대시보드 실행

PowerShell에서 대시보드 프로젝트 폴더로 이동한 뒤 실행합니다.

~~~powershell
cd "C:\EyetoArm\dashboard-client"
$env:PYTHONPATH = (Resolve-Path .\src).Path
python -m eyetoarm.gui.window --host 127.0.0.1 --port 47090 --view relay --view-host 127.0.0.1 --view-port 47092
~~~

대시보드에서 C 서버 연결 상태와 보류 사유를 확인하고, 영상 영역에 링크·그리퍼·고정 카메라 화면이 표시되는지 확인합니다.

### PS. 볼트 잡기 데모

Gazebo와 로봇 제어가 실행 중이고 컨베이어가 멈춰 있는 상태에서, 새 WSL 터미널을 열어 실행합니다. Gazebo와 같은 ROS_DOMAIN_ID를 사용해야 합니다.

~~~bash
cd ~/EyetoArm
source /opt/ros/jazzy/setup.bash
source ~/EyetoArm/robot_ws/install/setup.bash
python3 scripts/pick_bolt_demo.py --part part_01
~~~

part_01은 M6x40 볼트입니다. 데모는 Gazebo의 실제 볼트 위치를 읽어 접근·파지·들기·놓기를 시도합니다. MoveIt 충돌 검사는 사용하지 않으므로 실제 로봇에서는 실행하지 마세요.

## 터미널에서 각각 실행시키는 법

통합 launch 대신 각 프로세스를 별도의 WSL Ubuntu 터미널에서 실행할 때 사용합니다. 각 터미널에서 먼저 ROS와 워크스페이스 환경을 불러옵니다.

~~~bash
source /opt/ros/jazzy/setup.bash
cd ~/EyetoArm
source robot_ws/install/setup.bash
~~~

### TCP 서버

~~~bash
ros2 run robot_server_package tcp_server
~~~

기본 주소는 127.0.0.1:47090입니다. 시작 로그에서 TCP server listening을 확인합니다.

### Gazebo와 카메라 토픽

~~~bash
ros2 launch scripts/sim_sort_cell.launch.py gui:=false
~~~

별도 터미널에서 카메라 토픽을 확인합니다.

~~~bash
source /opt/ros/jazzy/setup.bash
cd ~/EyetoArm
source robot_ws/install/setup.bash
ros2 topic list | grep -E '^/(link_cam/image|gripper_cam/image|overview_cam/image)$'
~~~

다음 토픽이 보여야 합니다: /link_cam/image, /gripper_cam/image, /overview_cam/image.

### 벨트만 수동으로 이동

Gazebo 월드가 실행된 뒤 새 WSL 터미널에서 벨트를 0.012 m/s로 구동합니다. 자동 분류 실행 중에는 시작·정지 서비스가 벨트를 제어합니다.

~~~bash
source /opt/ros/jazzy/setup.bash
gz topic -t /model/conveyor/link/link/track_cmd_vel -m gz.msgs.Double -p 'data: 0.012'
~~~

벨트를 멈추려면 속도 0을 보냅니다.

~~~bash
gz topic -t /model/conveyor/link/link/track_cmd_vel -m gz.msgs.Double -p 'data: 0.0'
~~~

### 영상 중계기

Gazebo 카메라 토픽이 확인된 뒤 새 터미널에서 실행합니다.

~~~bash
source /opt/ros/jazzy/setup.bash
cd ~/EyetoArm
source robot_ws/install/setup.bash
ros2 run robot_server_package display_relay
~~~

중계기는 기본적으로 0.0.0.0:47092에서 대시보드의 접속을 기다립니다. 로그의 rx는 Gazebo 토픽에서 C가 받은 FPS, tx는 TCP로 D에 보낸 FPS입니다. 영상 전송은 명령·상태 TCP 47090과 별도 포트 47092를 사용합니다.

### 종료

각 프로세스가 실행 중인 터미널에서 Ctrl+C를 누릅니다. 대시보드만 종료해도 Ubuntu의 C 서버 프로세스는 계속 실행됩니다.
