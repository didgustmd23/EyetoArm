이 문서는 A가 B·C·D에게 보내는 협업 요청의 **초안**입니다. 아래 「A 제안」은 협의 출발점일 뿐 합의가 아닙니다. 회신이 없는 항목을 합의로 보지 않습니다. 요청 기한은 모두 제안입니다. 이 문서는 팀원에게 메시지를 보내거나 회신을 대신 작성한 기록이 아닙니다.

**읽는 방법.** 위 「원본」 표의 단계 1 결과와 A의 1주차 계획은 A의 로컬 작업 기록(Git 제외)이라 팀원은 볼 수 없습니다. 이 문서와 Git에 있는 공유 설계 문서만으로 회신할 수 있도록 썼습니다. 기한의 「n일차」는 A의 1주차 작업 일정(1~5일차, 1일차 = 2026-11-10) 기준입니다. A는 2026-11-11에 3일차 작업까지 앞당겨 진행했으므로 「2일차 구현 전」 같은 일부 기한은 이미 지났습니다. 지난 기한의 항목도 회신은 여전히 필요합니다. 0.2에서 갱신한 항목은 기한을 새로 적었습니다. 팀 일정과 맞지 않으면 회신에서 조정해 주세요.

## 1. 이미 정해진 사항 (회신·재승인 대상 아님)

- **사용자 확정:** 최종 부품 M6×12·M6×40 볼트와 M6 너트(축 길이로 구분), 스마트폰 실사용은 4~5주차(1주차는 입력 어댑터·설정 형식만), C 월드 녹화는 월드 구성 완료 후 확보, AI 검출 모델은 후보 비교 후 선정.
- **기존 확정 규칙:** 너트는 방향 판정 불필요(B §7.2), 규격·유효성 최종 판정은 B. A의 운영 비전 모듈은 팔·벨트 명령을 만들지 않음.
- **단위 규칙:** B 결과 자료형의 위치·치수는 **m**이고, 화면 표시와 TCP 경계에서 D가 **mm로 한 번만** 변환합니다(B §5.5). 새 합의 대상이 아니며, B 구현이 이 규칙과 일치하는지 확인하는 것은 B 내부 사항입니다.
- **담당 경계:** A 카메라 영상 입력·검출·추적·관측 출력, B 좌표·규격·판정·목표, C 서버·로봇 실행·월드와 실행 피드백(도착·접촉·부착·벨트 정지 확인), D GUI·클라이언트(계획서 §2.6.2·§3, 2026-11-11 실행 피드백 경계 사용자 확정).
- **2026-11-11 사용자 확정(설계 반영됨):** D 운영 GUI·TCP 클라이언트는 Windows, A·B·C와 ROS/MoveIt/Gazebo는 WSL. A→B는 공통 자료형·내부 호출로 함께 동작하는 파이프라인이며 별도 ROS 인터페이스를 만들지 않음. B→C 자동 분류 목표는 ROS 액션이고 C가 검증·계획·실행·취소·결과를 책임짐. GUI가 START·STOP·RECOVER를 보내며 GUI↔C는 TCP 서버·수신 포트·연결·처리기 각 하나(별도 확장 listener·포트·계약 없음, 메시지 형식은 TCP 명세서 부록 A 개정 제안·미승인). 별도 자동운전 모드 없음. 영상은 로봇 명령 TCP에 넣지 않음.

## 3. B에게 요청 (6건)

### B-01 픽셀·왜곡 보정

- **배경:** 왜곡 보정(렌즈 휨을 펴는 계산)을 A와 B가 둘 다 적용하거나 둘 다 빠뜨리면 좌표가 어긋납니다.
- **A 제안:** A가 원본(`raw`) 픽셀 윤곽을 전달하고, B가 왜곡 보정과 작업 좌표 변환을 맡습니다.
- **확인할 내용:** A가 넘길 픽셀 기준(`raw`/보정 후)과 보정 적용 담당, 영상/점 보정 순서, 프로파일 필드. 보정은 한 번만 적용.
- **제안 기한:** 2일차 구현 전.
- **미회신 영향:** A는 원본 픽셀 윤곽과 `pixel_basis` 기록까지만 진행하고, 보정 적용·좌표 변환은 하지 않습니다.
- **근거:** A §5.2·§12, B §6.1·§6.2. 공통 자료형 초안 §3.1 `PixelBasis`·`Contour`.

### B-02 ROI·표시 축소 복원과 프로파일 불일치

- **배경:** ROI(영상 관심 영역)로 잘라 처리한 윤곽을 원본 좌표로 되돌리지 않거나, 해상도·크롭이 보정 프로파일(카메라별 보정값 묶음)과 다르면 B 변환이 틀린 위치를 냅니다.
- **A 제안:** A가 ROI·표시 축소 좌표를 원본 해상도 좌표로 복원하고 변환 정보를 함께 기록합니다.
- **확인할 내용:** B가 기대하는 원점·스케일, width/height/crop/`calibration_id` 불일치 처리(무효 사유 이름·판정 담당).
- **제안 기한:** 2일차 구현 전.
- **미회신 영향:** ROI 오프셋 복원과 불일치 시 무효 표시까지 진행합니다. 프로파일 필드 이름은 제안으로 둡니다.
- **근거:** A §5.1·§5.4(`CALIBRATION_MISMATCH`), B §6.1. 공통 자료형 초안 §3.1 `PixelToSourceTransform`(전달 방식 미결).

### B-03 부품 관측면·기준점

- **배경:** 기존 윗면(`top_face`) 계약은 판형 부품 기준이라, 머리·축이 누운 볼트와 너트에서 어느 면 윤곽을 넘겨야 B의 높이 변환과 맞는지 정해지지 않았습니다.
- **A 제안:** 표시용 전체 마스크와 계산용 윤곽을 구분하고, 부품별 관측면을 파일럿으로 정합니다. 판형 `top_face`를 강제하지 않습니다.
- **확인할 내용:** 볼트 머리/축·너트의 관측면·기준점·변환 평면, 또는 이를 정할 파일럿의 담당·결정 기한.
- **제안 기한:** 3일차 기준 검출 전.
- **미회신 영향:** 계산용 윤곽은 "미확정"(`observed_face = None`, 무효)으로 두고 표시용만 출력합니다. B 유효 결과를 만들지 않습니다.
- **근거:** A §1 「관측면 주의」·§5.2·§12, B §1·§13. 공통 자료형 초안 §3.3 유효 조건.

### B-04 볼트 길이 측정에 필요한 계산용 윤곽 범위 (0.5 축소)

- **배경:** 두 볼트는 축 길이(12 / 40 mm)로만 구분됩니다. 메시 기준 머리 포함 전체 길이는 약 18 / 46 mm입니다. B가 길이를 머리 포함 전체로 재는지 축만 재는지에 따라 A가 넘길 계산용 윤곽에 머리를 포함해야 하는지가 달라집니다.
- **A 제안:** 머리 포함 전체와 축만의 두 범위 중 영상에서 안정적인 쪽을 파일럿으로 비교합니다. 길이 기준점·허용 범위·`UNRESOLVED` 조건은 B가 정하며(B §12) 이 요청의 회신 대상이 아닙니다.
- **확인할 내용:** A가 넘길 계산용 윤곽이 길이 측정에 필요한 범위(머리 포함 여부)와 그 결정 시점. 모델 선정 자체는 회신 대상이 아닙니다.
- **제안 기한:** 2일차 구현 전.
- **미회신 영향:** 공개 데이터 Bolt/Nut 이미지로 검출 실험만 합니다. 규격 정답·성능으로 쓰지 않습니다.
- **근거:** 계획서 §2.6.1, B §12·§13, `simulation/models/*/model.sdf`.

### B-05 AI 클래스 구성

- **배경:** 3클래스와 `bolt`·`nut` 2클래스 + 치수 판정 중 무엇을 고르느냐에 따라 라벨 작업과 데이터 분할이 달라집니다.
- **A 제안:** 공개 자료를 활용하는 2클래스 + B 치수 판정을 우선 검토합니다(채택 확정 아님). 3클래스 대안과 같은 조건으로 파일럿해 결정합니다.
- **확인할 내용:** 파일럿 표본 수·촬영 조건, 결정 기한(설계상 3주차 평가 전 고정).
- **제안 기한:** 1주차 5일차 데이터 계획 전.
- **미회신 영향:** 2클래스 공개 라벨 기준으로 자료 목록만 작성합니다.
- **근거:** A §7.1·§12, 계획서 §2.6.1.

### B-07 A→B 전달 자료형과 A가 보존할 식별자 (0.2 추가, 0.5 축소)

- **배경:** A→B는 별도 ROS 인터페이스 없이 함께 동작하는 파이프라인입니다(사용자 확정). A가 넘기는 자료형과 식별자가 B의 기대와 다르면 B 결과가 어느 프레임·처리 세대에 속하는지 추적할 수 없습니다.
- **A 제안:** A는 공통형 `FramePacket`과 A 관측형을 B에 넘기고, 근거 식별자를 바꾸지 않고 그대로 보존해 넘깁니다.
- **확인할 내용:** B가 받는 자료형(공통형 `FramePacket`·A 관측형)과, A가 보존해 넘길 식별자(`part_track_id`, 근거 프레임, `generation`·`job_seq`)가 B의 기대와 맞는지.
- **제안 기한:** 2주차 통합 전.
- **미회신 영향:** A는 자기 모듈의 관측 출력과 식별자 보존까지 진행합니다.
- **근거:** 계획서 §2.1, A §3·§12, B §3·§15.4. 액션 필드 상세는 C 상세설계 §16.8.5가 기준이며 이 문서에서 새로 정하지 않습니다.

## 4. C에게 요청 (5건)

### D-01 Windows GUI로의 결과·측정값 전달 (0.2 갱신)

### D-06 통신 시험에서 쓸 TCP 클라이언트 (0.2 갱신)

- **배경:** A의 통신 시험 도구는 운영 클라이언트를 중복 구현하지 않고 D 클라이언트를 재사용합니다(0.1 수락 내용). 현재 저장소에는 D의 표준 라이브러리 asyncio 클라이언트 `src/eyetoarm/tcp/client.py`의 `TcpClient`가 있으며, `connect`·`disconnect`·`query_ready`·`execute`·`cancel`·`snapshot` 함수가 보입니다. **함수가 있다는 것만 확인했고, A 시험 도구와의 호환·동작은 확인하지 않았습니다.**
- **A 제안:** 시험 도구는 WSL에서 `TcpClient`를 직접 불러 쓰는 것을 우선 검토합니다. GUI(PySide6)와 분리된 모듈만 쓰고, 장애 주입은 시험 모드에서만 합니다(TCP 명세서 §8.6).
- **확인할 내용:** 재사용해도 되는 공개 API 범위와 안정성(내부 `_` 함수 제외), 실행 조건(asyncio 이벤트 루프를 누가 돌리는지, `connect`가 루프 안에서 불려야 하는지), `EventLog` 기록 위치·형식과 시험 기록의 분리, 지원 프로토콜 버전(현재 1.1. 부록 A 개정 메시지는 미승인), WSL 시험 도구가 C 서버에 붙는 주소, WSL 시험 도구가 쓰는 공용 코드(`src/eyetoarm/tcp/`)의 지원 Python·버전 범위, 이후 변경 시 알림 방법.
- **제안 기한:** 통신 시험 도구 구현 전(2주차).
- **미회신 영향:** 통신 시험 시나리오, 입출력 어댑터 설계, 결과 집계 형식은 계속 진행합니다. `TcpClient`를 호출하는 부분만 API 확인 뒤에 연결합니다. 이번 검토로 클라이언트 API가 최종 승인된 것은 아닙니다.
- **근거:** A §2·§12, 계획서 §3 통신 시험 분담, D §A.11, `src/eyetoarm/tcp/client.py`, TCP 명세서 §8.

A §5의 문서상 규칙이 각 담당의 기록·표시·판정과 같은 해석인지 확인합니다. 공통 자료형 초안 §4 불변조건과 같습니다. (원본 §4.5 「A 확인·공동 확인 항목」을 여기에 합침)

## 8. 범위

- 1~3주차 평면 분류의 내부 자료형·입력 계약과, A/B가 출력·소비하는 분류 실행 경계(B-07·C-07)가 대상입니다. 6D와 사람 자세는 포함하지 않습니다.
- 로봇 명령·실행 자료형 전체와 ROS 액션 상세 필드는 이 문서에서 정하지 않고 C 상세설계 §16.8.5를 기준으로 참조합니다.
- TCP 1.1 스키마·명령 의미와 기존 담당 경계는 변경 요청 대상이 아닙니다. GUI의 START·STOP·RECOVER는 단일 TCP 서버·포트·연결·처리기의 개정 제안(TCP 명세서 부록 A, 미승인)이며, 별도 자동운전 모드나 별도 TCP 확장 서버를 만들지 않습니다.
- 이 문서는 실제 발송·구현 승인을 포함하지 않습니다.
