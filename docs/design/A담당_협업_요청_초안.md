이 문서는 A가 B·C·D에게 보낼 협업 요청의 **초안**입니다. 아직 아무에게도 보내지 않았고, 아래 「A 제안」은 협의 출발점일 뿐 합의가 아닙니다. 회신이 없는 항목을 합의로 보지 않습니다. 요청 기한은 모두 제안입니다.

**읽는 방법.** 위 「원본」 표의 단계 1 결과와 A의 1주차 계획은 A의 로컬 작업 기록(Git 제외)이라 팀원은 볼 수 없습니다. 이 문서와 Git에 있는 공유 설계 문서만으로 회신할 수 있도록 썼습니다. 기한의 「n일차」는 A의 1주차 작업 일정(1~5일차, 1일차 = 2026-11-10) 기준입니다. 각 기한에는 그 시점의 A 작업(예: 「2일차 구현 전」, 「4일차 연동 전」)을 함께 적었습니다. 팀 일정과 맞지 않으면 회신에서 조정해 주세요.

## 1. 이미 정해진 사항 (회신·재승인 대상 아님)

- **사용자 확정:** 최종 부품 M6×12·M6×40 볼트와 M6 너트(축 길이로 구분), 스마트폰 실사용은 4~5주차(1주차는 입력 어댑터·설정 형식만), C 월드 녹화는 월드 구성 완료 후 확보, AI 검출 모델은 후보 비교 후 선정.
- **기존 확정 규칙:** 너트는 방향 판정 불필요(B §7.2), 규격·유효성 최종 판정은 B. A의 운영 비전 모듈은 팔·벨트 명령을 만들지 않음.
- **단위 규칙:** B 결과 자료형의 위치·치수는 **m**이고, 화면 표시와 TCP 경계에서 D가 **mm로 한 번만** 변환합니다(B §5.5). 새 합의 대상이 아니며, 구현이 이 규칙과 일치하는지만 확인합니다(B-06).
- **담당 경계:** A 인식·센서 입력, B 좌표·규격·판정, C 서버·로봇 실행·월드, D GUI·클라이언트(계획서 §3).

## 3. B에게 요청 (6건)

### B-01 픽셀·왜곡 보정

- **배경:** 왜곡 보정(렌즈 휨을 펴는 계산)을 A와 B가 둘 다 적용하거나 둘 다 빠뜨리면 좌표가 어긋납니다.
- **A 제안:** A가 원본(`raw`) 픽셀 윤곽을 전달하고, B가 왜곡 보정과 작업 좌표 변환을 맡습니다.
- **확인할 내용:** A가 넘길 픽셀 기준(`raw`/보정 후)과 보정 적용 담당, 영상/점 보정 순서, 프로파일 필드. 보정은 한 번만 적용.
- **제안 기한:** 2일차 구현 전.
- **미회신 영향:** A는 원본 픽셀 윤곽과 `pixel_basis` 기록까지만 진행하고, 보정 적용·좌표 변환은 하지 않습니다.
- **근거:** A §5.2·§12, B §6.1·§6.2. 공통 자료형 초안 §3.1 `PixelBasis`·`Contour`.

### B-02 ROI·표시 축소 복원과 프로파일 불일치

- **배경:** ROI(영상 관심 영역)로 잘라 처리한 윤곽을 원본 좌표로 되돌리지 않거나, 해상도·크롭이 보정 프로파일(카메라별 보정값 묶음)과 다르면 B 변환이 틀린 위치를 냅니다.
- **A 제안:** A가 ROI·표시 축소 좌표를 원본 해상도 좌표로 복원하고 변환 정보를 함께 기록합니다.
- **확인할 내용:** B가 기대하는 원점·스케일, width/height/crop/`calibration_id` 불일치 처리(무효 사유 이름·판정 담당).
- **제안 기한:** 2일차 구현 전.
- **미회신 영향:** ROI 오프셋 복원과 불일치 시 무효 표시까지 진행합니다. 프로파일 필드 이름은 제안으로 둡니다.
- **근거:** A §5.1·§5.4(`CALIBRATION_MISMATCH`), B §6.1. 공통 자료형 초안 §3.1 `PixelToSourceTransform`(전달 방식 미결).

### B-03 부품 관측면·기준점

- **배경:** 기존 윗면(`top_face`) 계약은 판형 부품 기준이라, 머리·축이 누운 볼트와 너트에서 어느 면 윤곽을 넘겨야 B의 높이 변환과 맞는지 정해지지 않았습니다.
- **A 제안:** 표시용 전체 마스크와 계산용 윤곽을 구분하고, 부품별 관측면을 파일럿으로 정합니다. 판형 `top_face`를 강제하지 않습니다.
- **확인할 내용:** 볼트 머리/축·너트의 관측면·기준점·변환 평면, 또는 이를 정할 파일럿의 담당·결정 기한.
- **제안 기한:** 3일차 기준 검출 전.
- **미회신 영향:** 계산용 윤곽은 "미확정"(`observed_face = None`, 무효)으로 두고 표시용만 출력합니다. B 유효 결과를 만들지 않습니다.
- **근거:** A §1 「관측면 주의」·§5.2·§12, B §1·§13. 공통 자료형 초안 §3.3 유효 조건.

### B-04 볼트 길이 판정 설정

- **배경:** 최종 모델은 확정됐고 두 볼트는 축 길이(12 / 40 mm)로만 구분됩니다. 메시 기준 머리 포함 전체 길이는 약 18 / 46 mm, 너트는 설정상 맞변 10 mm·두께 5.2 mm입니다. 머리를 포함해 잴지, 축만 잴지와 허용 범위가 정해져야 판정과 계산용 윤곽이 맞습니다.
- **A 제안:** 머리 포함 전체 길이와 축 길이 중 영상에서 안정적인 기준을 파일럿으로 고릅니다.
- **확인할 내용:** 측정 기준점, 투영 보정, 허용 범위, `UNRESOLVED` 조건, 관측면·파지 설정의 결정 담당·시점. 모델 선정 자체는 회신 대상이 아닙니다.
- **제안 기한:** 기준점은 2일차 구현 전, 허용 범위는 2주차 파일럿.
- **미회신 영향:** 공개 데이터 Bolt/Nut 이미지로 검출 실험만 합니다. 규격 정답·성능으로 쓰지 않습니다.
- **근거:** 컨베이어 분류 상세설계 §1.1·§1.2, B §13, `simulation/models/*/model.sdf`.

### B-05 AI 클래스 구성

- **배경:** 3클래스와 `bolt`·`nut` 2클래스 + 치수 판정 중 무엇을 고르느냐에 따라 라벨 작업과 데이터 분할이 달라집니다.
- **A 제안:** 공개 자료를 활용하는 2클래스 + B 치수 판정을 우선 검토합니다(채택 확정 아님). 3클래스 대안과 같은 조건으로 파일럿해 결정합니다.
- **확인할 내용:** 파일럿 표본 수·촬영 조건, 결정 기한(설계상 3주차 평가 전 고정).
- **제안 기한:** 1주차 5일차 데이터 계획 전.
- **미회신 영향:** 2클래스 공개 라벨 기준으로 자료 목록만 작성합니다.
- **근거:** A §7.1·§12, 컨베이어 분류 §1.2.

### B-06 결과 필드·판정 경계·단위의 구현 일치 확인

- **배경:** A·B 판정 경계, 너트 방향 불필요, B 결과의 m 단위는 이미 확정된 규칙입니다. 다시 승인받을 사항이 아니라 B 쪽 구현이 이 규칙과 맞는지 확인할 사항입니다.
- **A 제안:** A는 픽셀 후보(클래스·신뢰도·윤곽)를 내고, B는 작업 좌표(m)·볼트 각도·규격·최종 유효성을 출력합니다. 화면·TCP의 mm 변환은 D가 한 번 합니다.
- **확인할 내용:** B 판정 코드·자료형이 ① 볼트에만 장변/단변 1.5 조건을 적용하고 너트에 장축각을 요구하지 않는지 ② 결과 위치·치수를 m로 내고 mm 필드를 함께 두지 않는지 ③ 공통 자료형 초안 §3.4 `WorkPlanarResult` 제안 필드(`center_w_m`, `theta_deg`, `theta_valid`, `spec`, `measured_length_m`, `calibration_id`, `transform_config_id`, `valid`, `reason`, `reason_owner`)와 유효 조건에 누락·불필요 항목이 있는지. 자료형 변경 담당과 D 전달 호환성도 함께.
- **제안 기한:** 3일차 B 인계 전.
- **미회신 영향:** A는 클래스 후보·윤곽만 출력하고 방향·규격 판정을 하지 않습니다.
- **근거:** A §5.2·§7, B §5.5·§7.2·§7.3. 공통 자료형 초안 §3.4. (원본 §4.5의 B 요청 1·2를 이 항목에 합침)

## 4. C에게 요청 (5건)

C의 회신은 Gazebo 입력·센서 연동의 일정에 필요합니다. **월드·녹화 확보는 저장 입력용 공통 자료형 구현의 선행조건이 아닙니다.** 공통 자료형과 저장 입력 작업은 공개 저장 자료로 먼저 진행합니다.

### C-01 Gazebo 카메라 토픽·광학 프레임·브리지

- **배경:** CameraInfo(카메라 보정 정보)와 광학 프레임(카메라 좌표계) 이름이 실제와 다르면 A의 ROS 입력이 영상을 받지 못하거나 B가 잘못된 좌표계로 계산합니다. 현재 월드의 `appearance_check_cam`은 D의 외형 확인용이며 운영 카메라가 아닙니다.
- **확인할 내용:** 운영 카메라의 `Image`·`CameraInfo` 토픽 이름, `optical_frame_id`, `ros_gz_bridge` 구성의 실제(또는 제안) 값과 준비 담당·날짜. 이 중 C가 제공·확정할 항목.
- **제안 기한:** 4일차 연동 전(설계상 1주차 합의는 유지).
- **미회신 영향:** 저장 영상 입력을 진행하고, 스마트폰은 어댑터·설정 형식만 준비합니다. ROS 입력 어댑터는 토픽 이름을 설정값으로 두고 실연동 미완료로 기록합니다.
- **근거:** A §12, 계획서 §2.2, C §8.1. (원본 §4.5 C 요청 2)

### C-02 도착 감지·접촉 센서

- **배경:** 형식과 대상 ID를 모르면 A가 입력을 구성할 수 없고, 어떤 부품의 신호인지 C의 판정과 맞출 수 없습니다.
- **확인할 내용:** 메시지 형식(토픽·필드), 부품 풀 ID 대응, 시각 기준, 수신 주기. 센서 상태를 공통 입력 계약에 넣을지, 넣는다면 C가 소유할 상태·메시지 자료형과 A·D 소비 경계.
- **제안 기한:** 4일차 연동 전.
- **미회신 영향:** 입력 구성 초안만 둡니다. 미수신·오래된 메시지는 "불명"으로 전달하고 미도착·비접촉으로 확정하지 않습니다. 서버·로봇 실행 자료형은 C 소유 그대로입니다.
- **근거:** A §12, 그리퍼·로봇 실행 상세설계 §7.3·§7.4, 컨베이어 분류 §2. (원본 §4.5 C 요청 4)

### C-03 시각 기준·되감기·단절

- **배경:** 시뮬레이션 시간과 PC 수신 시각을 섞어 빼면 지연·유효 시간이 틀리고, 일시정지·되감기 뒤 옛 영상이 새 결과처럼 쓰일 수 있습니다.
- **A 제안(문서상 규칙):** `SIM_TIME`·ROS 원본 stamp와 PC 수신 단조 시각을 따로 보관하고, 시간 되감기는 세대 증가로 처리합니다.
- **확인할 내용:** C가 제공하는 시각 필드·기준, 일시정지·되감기·브리지 단절 때 C가 기대하는 A의 표시·무효화. 이 규칙이 C의 Gazebo·서버 운용과 맞는지.
- **제안 기한:** 4일차 연동 전.
- **미회신 영향:** A 규칙대로 두 시각 분리·세대 증가를 구현 대상으로 두고, C 기대와 다르면 재조정합니다.
- **근거:** A §5.1 「시각 관계」·§5.4, 계획서 §2.2. 공통 자료형 초안 §4 불변조건 3·4. (원본 §4.5 C 요청 1)

### C-04 월드 완료 시점과 녹화

- **배경:** 녹화는 C 월드 구성 완료 후 확보합니다(사용자 확정, 고정 기한 아님). 완료 시점을 알아야 A의 수신 확인 일정을 잡고 연동 지연 위험을 기록할 수 있습니다.
- **확인할 내용:** 월드 완료 예정 시점, 완료 후 녹화(rosbag 등) 제공 시점·형식(토픽 목록·길이)·전달 경로.
- **제안 기한:** 월드 완료 예정 시점 회신은 3일차 중. 녹화는 월드 완료 후.
- **미회신 영향:** 공개 저장 이미지로 계속 진행합니다. 녹화를 받으면 A가 수신·디코딩·검출을 확인합니다. 공통 자료형·저장 입력 구현은 이 회신을 기다리지 않습니다.
- **근거:** C §11 1주차, 계획서 §5(1주차). (원본 §4.5 C 요청 3)

### C-05 카메라 Hz·RTF 측정 조건

- **배경:** C의 카메라 Hz·RTF(시뮬레이션 실시간 비율) 측정과 A의 수신률 측정 조건이 다르면 비교할 수 없습니다.
- **확인할 내용:** C의 측정 조건(해상도·갱신률·렌더링 방식), 결과 기록 위치, 공유 시점.
- **제안 기한:** 4일차 연동 전.
- **미회신 영향:** A는 자체 수신률만 기록하고 C 결과와의 대조는 기다립니다.
- **근거:** C §8.1·§12, 계획서 §5 완료 기준.

## 5. D에게 요청 (6건)

### D-01 결과 전달·GUI 스레드

- **배경:** 전달 방식이 정해지지 않으면 GUI 스레드(화면 갱신 전용 실행 흐름) 밖에서 화면 객체를 건드려 앱이 멈추거나 깨질 수 있습니다.
- **A 제안:** 영상 수신과 처리는 GUI 밖, 화면 갱신은 GUI 스레드에서.
- **확인할 내용:** D가 제공할 전달 API(시그널·대기열 등)와 동기화, `FramePacket`·`PlanarObservation`·`WorkPlanarResult`를 GUI·TCP 경계에서 소비하는 필드와 mm 변환 위치(D가 한 번).
- **제안 기한:** 2일차 구현 전.
- **미회신 영향:** A 내부 자료형과 콜백 경계를 제안으로 구현하고 GUI 연결은 하지 않습니다.
- **근거:** A §3·§5.1·§5.2·§12, D §A.4, B §5.5. 공통 자료형 초안 §3. (원본 §4.5 D 요청 2·5)

### D-02 버퍼·대기열

- **배경:** 버퍼 수명(영상 메모리를 안전하게 참조할 수 있는 기간)이 맞지 않으면 처리 중인 영상이 덮어써져 화면과 결과가 다른 프레임을 가리킬 수 있습니다. NumPy 읽기 전용 표시만으로는 다른 별칭이나 생산자의 버퍼 재사용을 막지 못합니다.
- **A 제안:** 최신 대기 프레임 1개, 처리 중 영상 보존, 폐기 수 기록. 생산자는 넘긴 버퍼를 재사용하지 않고, 소유권 양도 또는 독립 복사로 넘깁니다.
- **확인할 내용:** 소유권 양도/독립 복사 중 정책, 표시 중 재사용 금지 보장 위치, D 표시 구조와의 호환성.
- **제안 기한:** 2일차 구현 전.
- **미회신 영향:** 제안 정책으로 입력 어댑터를 구현하고 표시 연결은 기다립니다.
- **근거:** A §3·§9. 공통 자료형 초안 §4 불변조건 8. (원본 §4.5 D 요청 3)

### D-03 무효화 이벤트

- **배경:** 세대/무효화(조건 변경·오류 뒤 이전 후보를 쓰지 못하게 하는 규칙)의 이벤트가 GUI에 전달되지 않으면 사용자가 옛 후보를 실행할 수 있습니다.
- **A 제안:** 처리 세대·작업 순번·원인·프레임 식별자를 전달합니다. 세대 변경도 같은 무효화 이벤트로 알리고, 프레임 없는 오류에 가짜 `image_seq`·`job_seq`를 만들지 않습니다(A §5.4 규칙 유지).
- **확인할 내용:** 이벤트·필드 이름, 전달 API, 입력 상태 이벤트와의 구분, D 수신 반영.
- **제안 기한:** 2일차 구현 전.
- **미회신 영향:** 이벤트를 내부 기록으로만 남기고 GUI 전달은 기다립니다.
- **근거:** A §5.4·§12, D §A.3·§A.6. 공통 자료형 초안 §3.5·§3.6. (원본 §4.5 D 요청 4)

### D-04 공통 자료형 파일 담당

- **배경:** 공동 파일 `src/eyetoarm/common/types.py`를 누가 만들고 승인하는지 정하지 않으면 A·B·D가 서로 다른 자료형을 만들 위험이 있습니다. 파일은 아직 없습니다.
- **A 제안:** A가 [공통 자료형 관리 초안](공통_자료형_관리_초안.md)을 제안하고 B·D 확인 후 공동 사용합니다. A 소유로 확정한 것이 아닙니다.
- **확인할 내용:** 작성 담당·승인 담당, API 확정 위치(파일·문서). 공동 파일에 둘지, 담당별 모듈에 두고 공통 계약만 둘지.
- **제안 기한:** 2일차 구현 전.
- **미회신 영향:** A 쪽 자료형을 A 모듈 안에 임시로 두고 공동 파일은 만들지 않습니다.
- **근거:** A §4(`common/types.py` 배치), B §4, 계획서 §3 「공통 파일 소유자」, 공통 자료형 초안 §2. (원본 §4.5 D 요청 1)

### D-05 공통 설치 환경

- **배경:** 팀원 PC마다 OpenCV 버전·설치 경로가 다르면 같은 코드가 다른 결과를 낼 수 있습니다.
- **A 제안:** 현재 확인된 시스템 OpenCV 4.6.0·NumPy 1.26.4(apt) 구성을 출발점으로 제안합니다. 현 PC가 곧 팀 표준은 아닙니다.
- **확인할 내용:** D 환경과 PySide6 호환, 버전·설치 경로, pip·가상환경 방식.
- **제안 기한:** 2일차 구현 전.
- **미회신 영향:** 현재 환경 버전만 기록하고 재설치하지 않습니다. PySide6는 프로젝트 운영 GUI(D 담당)의 의존성이며, A의 저장 입력·검출 작업은 GUI 없이 진행하므로 이 회신의 필수 선행조건이 아닙니다. 현재 PC의 apt OpenCV는 설치돼 있다는 사실만 확인했고, 설치 주체·경위는 확인하지 않았습니다.
- **근거:** 계획서 §2.5, A §12, `requirements.txt`.

### D-06 통신 시험 API

- **배경:** A의 통신 시험 도구는 D 클라이언트를 재사용해야 하므로 제공 시점을 알아야 시험 일정을 잡을 수 있습니다.
- **A 제안:** A 시험 도구가 D 클라이언트를 재사용하고, 별도 운영 클라이언트를 중복 구현하지 않습니다.
- **확인할 내용:** 공개 함수·이벤트·오류/응답, 제공 예정일.
- **제안 기한:** 1주차 5일차(통신 시험 초안 전).
- **미회신 영향:** 통신 시험 시나리오 초안만 작성하고 도구는 구현하지 않습니다.
- **근거:** A §2·§12, 계획서 §3 통신 시험 분담.

## 6. 공통 대조 (B·C·D 전원, 4건)

A §5의 문서상 규칙이 각 담당의 기록·표시·판정과 같은 해석인지 확인합니다. 공통 자료형 초안 §4 불변조건과 같습니다. (원본 §4.5 「A 확인·공동 확인 항목」을 여기에 합침)

| ID | 대조 항목 | A §5 문서상 규칙 | 확인 대상 | 미회신 영향 |
|---|---|---|---|---|
| X-01 | run·source·image 식별자 수명 | `run_id`는 앱 실행마다 새로, `image_seq`는 같은 `run_id`에서 단조 증가하며 소스 변경·재접속·탐색·되감기로 초기화하지 않음 | B·C·D가 같은 규칙으로 기록·표시하는지 | A 규칙대로 구현하고 차이는 연동 때 확인 |
