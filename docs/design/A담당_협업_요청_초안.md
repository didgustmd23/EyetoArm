- **배경:** 왜곡 보정(렌즈 휨을 펴는 계산)을 A와 B가 둘 다 적용하거나 둘 다 빠뜨리면 좌표가 어긋납니다.

### B-02 ROI·표시 축소 복원과 프로파일 불일치

- **배경:** ROI(영상 관심 영역)로 잘라 처리한 윤곽을 원본 좌표로 되돌리지 않거나, 해상도·크롭이 보정 프로파일(카메라별 보정값 묶음)과 다르면 B 변환이 틀린 위치를 냅니다.
- **A 제안:** A가 ROI·표시 축소 좌표를 원본 해상도 좌표로 복원하고 변환 정보를 함께 기록합니다.
- **확인할 내용:** B가 기대하는 원점·스케일, width/height/crop/`calibration_id` 불일치 처리(무효 사유 이름·판정 담당).
- **제안 기한:** 2일차 구현 전.

### D-04 공통 자료형의 변경 관리와 소비 호환 (0.2 갱신)

- **배경:** `src/eyetoarm/common/types.py`는 이미 작성돼 있습니다. 최소 공통형 `TimestampBase`·`InputStatus`·`FramePacket`(14개 필드)·`InputStatusEvent`(5개 필드)가 들어 있고, `src/eyetoarm/inputs/base.py`가 이를 상속해 A 확장(`source_ref`·`source_index`)을 붙여 씁니다. `PlanarObservation`·`WorkPlanarResult`·`CandidateInvalidationEvent` 같은 관측·결과·사건형은 아직 구현하지 않았습니다.
- **A 제안:** 이미 쓰는 최소 공통형은 공통 자료형 초안 §3 기준으로 계속 쓰고, 다시 승인 대기로 돌리지 않습니다. 앞으로의 필드 변경과 미구현 자료형 추가는 초안 §6의 변경 관리 절차(영향 담당 확인)를 따릅니다.
- **확인할 내용:** ① 기존 최소형을 B·D가 소비할 때 필드 이름·타입·필수 여부가 맞는지(소비 호환, D는 표시·소비 호환 확인), ② 미구현 관측·결과·사건형의 필드 정의 시점(B 결과형은 B가 의미·단위·유효 조건 정의). ③ 공통 파일 관리·변경 반영·호환성 확인 담당은 **A로 결정**(사용자 결정 2026-11-11, 계획서 §3)되어 회신 대상에서 뺐습니다.
- **제안 기한:** ①은 B·D가 처음 소비하기 전, ②는 각 자료형 구현 전.
- **미회신 영향:** A는 기존 공통형을 계속 쓰고, 미구현 자료형은 A 모듈 안의 제안형으로 둡니다. 공통 파일을 지우거나 다시 만들지 않습니다. 공통 파일 변경은 영향 담당 확인 뒤 A가 반영합니다.
- **근거:** `src/eyetoarm/common/types.py`, `src/eyetoarm/inputs/base.py`, A §4, 공통 자료형 초안 §2·§3·§6, 계획서 §3.
- **회신:** A 제안 수락(D, 사용자 전달 2026-11-12, 원문 미확인). 확정: 기존 최소 공통형을 계속 쓰고 이후 변경은 공통 자료형 초안 §6 절차를 따름. **미결:** 미구현 관측·결과·사건형의 필드 정의 시점.

### D-06 통신 시험에서 쓸 TCP 클라이언트 (0.2 갱신)

- **배경:** A의 통신 시험 도구는 운영 클라이언트를 중복 구현하지 않고 D 클라이언트를 재사용합니다(0.1 수락 내용). 현재 저장소에는 D의 표준 라이브러리 asyncio 클라이언트 `src/eyetoarm/tcp/client.py`의 `TcpClient`가 있으며, `connect`·`disconnect`·`query_ready`·`execute`·`cancel`·`snapshot` 함수가 보입니다. **함수가 있다는 것만 확인했고, A 시험 도구와의 호환·동작은 확인하지 않았습니다.**
- **A 제안:** 시험 도구는 WSL에서 `TcpClient`를 직접 불러 쓰는 것을 우선 검토합니다. GUI(PySide6)와 분리된 모듈만 쓰고, 장애 주입은 시험 모드에서만 합니다(TCP 명세서 §8.6).
- **확인할 내용:** 재사용해도 되는 공개 API 범위와 안정성(내부 `_` 함수 제외), 실행 조건(asyncio 이벤트 루프를 누가 돌리는지, `connect`가 루프 안에서 불려야 하는지), `EventLog` 기록 위치·형식과 시험 기록의 분리, 지원 프로토콜 버전(현재 1.1. 부록 A 개정 메시지는 미승인), WSL 시험 도구가 C 서버에 붙는 주소, WSL 시험 도구가 쓰는 공용 코드(`src/eyetoarm/tcp/`)의 지원 Python·버전 범위, 이후 변경 시 알림 방법.
- **제안 기한:** 통신 시험 도구 구현 전(2주차).
- **미회신 영향:** 통신 시험 시나리오, 입출력 어댑터 설계, 결과 집계 형식은 계속 진행합니다. `TcpClient`를 호출하는 부분만 API 확인 뒤에 연결합니다. 이번 검토로 클라이언트 API가 최종 승인된 것은 아닙니다.
- **근거:** A §2·§12, 계획서 §3 통신 시험 분담, D §A.11, `src/eyetoarm/tcp/client.py`, TCP 명세서 §8.
- **회신:** A 제안 수락(D, 사용자 전달 2026-11-12, 원문 미확인). 확정: 시험 도구가 WSL에서 `TcpClient`를 직접 재사용하고 GUI(PySide6) 모듈과 분리하며 장애 주입은 시험 모드에서만. **미결:** 「확인할 내용」의 구체값(공개 API 범위, 이벤트 루프 조건, `EventLog` 위치·형식, 지원 프로토콜 버전, 접속 주소, 공용 코드 버전 범위, 변경 알림 방법). 클라이언트 API 최종 승인은 아님.

## 8. 범위

- 1~3주차 평면 분류의 내부 자료형·입력 계약(링크 카메라 입력 C-01 포함)과, A/B가 출력·소비하는 분류 실행 경계(B-07·C-07), 영상 표시 경로(A·B 주석 영상·결과·무효화 JSON → C → D, B-08·C-08·D-01~03)가 대상입니다. 6D와 사람 자세는 포함하지 않습니다.
- 로봇 명령·실행 자료형 전체와 ROS 액션 상세 필드는 이 문서에서 정하지 않고 C 상세설계 §16.8.5를 기준으로 참조합니다.
- TCP 1.1 스키마·명령 의미와 기존 담당 경계는 변경 요청 대상이 아닙니다. 영상 표시 경로는 TCP 1.1 명령 연결과 분리된 경로이며 TCP 명세서 §0을 바꾸지 않습니다. GUI의 START·STOP·RECOVER는 단일 TCP 서버·포트·연결·처리기의 개정 제안(TCP 명세서 부록 A, 미승인)이며, 별도 자동운전 모드나 별도 TCP 확장 서버를 만들지 않습니다.
- 이 문서는 실제 발송·구현 승인을 포함하지 않습니다.
