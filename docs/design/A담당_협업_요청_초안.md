이 문서는 A가 B·C·D에게 보내는 협업 요청의 **초안**입니다. 아래 「A 제안」은 협의 출발점일 뿐 합의가 아닙니다. 회신이 없는 항목을 합의로 보지 않습니다. 요청 기한은 모두 제안입니다. 이 문서는 팀원에게 메시지를 보내거나 회신을 대신 작성한 기록이 아닙니다.

**읽는 방법.** 위 「원본」 표의 단계 1 결과와 A의 1주차 계획은 A의 로컬 작업 기록(Git 제외)이라 팀원은 볼 수 없습니다. 이 문서와 Git에 있는 공유 설계 문서만으로 회신할 수 있도록 썼습니다. 기한의 「n일차」는 A의 1주차 작업 일정(1~5일차, 1일차 = 2026-11-10) 기준입니다. A는 2026-11-11에 3일차 작업까지 앞당겨 진행했으므로 「2일차 구현 전」 같은 일부 기한은 이미 지났습니다. 지난 기한의 항목도 회신은 여전히 필요합니다. 0.2에서 갱신한 항목은 기한을 새로 적었습니다. 팀 일정과 맞지 않으면 회신에서 조정해 주세요.

## 3. B에게 요청 (7건)

### B-01 픽셀·왜곡 보정

- **배경:** 왜곡 보정(렌즈 휨을 펴는 계산)을 A와 B가 둘 다 적용하거나 둘 다 빠뜨리면 좌표가 어긋납니다.
- **A 제안:** A가 원본(`raw`) 픽셀 윤곽을 전달하고, B가 왜곡 보정과 작업 좌표 변환을 맡습니다.
- **확인할 내용:** A가 넘길 픽셀 기준(`raw`/보정 후)과 보정 적용 담당, 영상/점 보정 순서, 프로파일 필드. 보정은 한 번만 적용.
- **제안 기한:** 2일차 구현 전.
- **미회신 영향:** A는 원본 픽셀 윤곽과 `pixel_basis` 기록까지만 진행하고, 보정 적용·좌표 변환은 하지 않습니다.
- **근거:** A §5.2·§12, B §6.1·§6.2. 공통 자료형 초안 §3.1 `PixelBasis`·`Contour`.

### B-02 ROI·표시 축소 복원과 프로파일 불일치

- **배경:** ROI(영상 관심 영역)로 잘라 처리한 윤곽을 원본 좌표로 되돌리지 않거나, 해상도·크롭이 보정 프로파일(카메라별 보정값 묶음)과 다르면 B 변환이 틀린 위치를 냅니다.
- **A 제안:** A가 ROI·표시 축소 좌표를 원본 해상도 좌표로 복원하고 변환 정보를 함께 기록합니다.
- **확인할 내용:** B가 기대하는 원점·스케일, width/height/crop/`calibration_id` 불일치 처리(무효 사유 이름·판정 담당).
- **제안 기한:** 2일차 구현 전.
- **미회신 영향:** ROI 오프셋 복원과 불일치 시 무효 표시까지 진행합니다. 프로파일 필드 이름은 제안으로 둡니다.
- **근거:** A §5.1·§5.4(`CALIBRATION_MISMATCH`), B §6.1. 공통 자료형 초안 §3.1 `PixelToSourceTransform`(전달 방식 미결).

### B-03 부품 관측면·기준점

- **배경:** 기존 윗면(`top_face`) 계약은 판형 부품 기준이라, 머리·축이 누운 볼트와 너트에서 어느 면 윤곽을 넘겨야 B의 높이 변환과 맞는지 정해지지 않았습니다.
- **A 제안:** 표시용 전체 마스크와 계산용 윤곽을 구분하고, 부품별 관측면을 파일럿으로 정합니다. 판형 `top_face`를 강제하지 않습니다.
- **확인할 내용:** 볼트 머리/축·너트의 관측면·기준점·변환 평면, 또는 이를 정할 파일럿의 담당·결정 기한.
- **제안 기한:** 3일차 기준 검출 전.
- **미회신 영향:** 계산용 윤곽은 "미확정"(`observed_face = None`, 무효)으로 두고 표시용만 출력합니다. B 유효 결과를 만들지 않습니다.
- **근거:** A §1 「관측면 주의」·§5.2·§12, B §1·§13. 공통 자료형 초안 §3.3 유효 조건.

### B-04 볼트 길이 판정 설정

- **배경:** 최종 모델은 확정됐고 두 볼트는 축 길이(12 / 40 mm)로만 구분됩니다. 메시 기준 머리 포함 전체 길이는 약 18 / 46 mm, 너트는 설정상 맞변 10 mm·두께 5.2 mm입니다. 머리를 포함해 잴지, 축만 잴지와 허용 범위가 정해져야 판정과 계산용 윤곽이 맞습니다.
- **A 제안:** 머리 포함 전체 길이와 축 길이 중 영상에서 안정적인 기준을 파일럿으로 고릅니다.
- **확인할 내용:** 측정 기준점, 투영 보정, 허용 범위, `UNRESOLVED` 조건, 관측면·파지 설정의 결정 담당·시점. 모델 선정 자체는 회신 대상이 아닙니다.
- **제안 기한:** 기준점은 2일차 구현 전, 허용 범위는 2주차 파일럿.
- **미회신 영향:** 공개 데이터 Bolt/Nut 이미지로 검출 실험만 합니다. 규격 정답·성능으로 쓰지 않습니다.
- **근거:** 계획서 §2.6.1, B §13, `simulation/models/*/model.sdf`.

### B-05 AI 클래스 구성

- **배경:** 3클래스와 `bolt`·`nut` 2클래스 + 치수 판정 중 무엇을 고르느냐에 따라 라벨 작업과 데이터 분할이 달라집니다.

### B-06 결과 필드·판정 경계·단위의 구현 일치 확인

- **배경:** A·B 판정 경계, 너트 방향 불필요, B 결과의 m 단위는 이미 확정된 규칙입니다. 다시 승인받을 사항이 아니라 B 쪽 구현이 이 규칙과 맞는지 확인할 사항입니다.

- **미회신 영향:** A는 클래스 후보·윤곽만 출력하고 방향·규격 판정을 하지 않습니다.
- **근거:** A §5.2·§7, B §5.5·§7.2·§7.3. 공통 자료형 초안 §3.4. (원본 §4.5의 B 요청 1·2를 이 항목에 합침)

### B-07 A·B 내부 파이프라인과 B→C 액션 클라이언트 경계 (0.2 추가)

- **배경:** A→B는 별도 ROS 인터페이스 없이 함께 동작하는 파이프라인이고(사용자 확정), B가 C에 ROS 액션 목표를 보냅니다. 파이프라인 실행 진입점(A)과 액션 클라이언트 어댑터(B)의 담당은 2026-11-11 사용자 결정으로 정해졌지만, 모듈 위치와 넘길 필드가 맞지 않으면 A의 출력 시점과 B의 목표 송신 조건이 어긋납니다.
- **A 제안:** A의 입력·검출·추적과 B의 순수 계산 함수를 한 프로세스의 파이프라인으로 묶고, 액션 클라이언트는 B 소유의 얇은 어댑터로 둡니다(B §3, C 상세설계 §16.8.5). 파이프라인 사이클 상태(`WATCH`·`STOP_SENT`·`REDETECT`·`PICK_SENT`·`ABORT_SENT`·`HANDED_OFF`)는 B 상세설계 §15.4의 B 소유 제안을 따릅니다.
- **확인할 내용:** 모듈 위치(실행 진입점 — 설정 로딩·영상 입력 연결·A→B 호출 배선·종료 정리 — 은 A, 계산 함수·액션 어댑터는 B로 결정됨, 사용자 결정 2026-11-11), B가 목표·판정을 받는 자료형(공통형 `FramePacket`·A 관측형 → B 결과형), 액션 클라이언트 어댑터 위치, goal에 실을 A 출처 필드(`part_track_id`, 근거 프레임, `generation`·`job_seq`)를 A가 그대로 넘기는지.
- **제안 기한:** 2주차 통합 전.
- **미회신 영향:** A는 자기 모듈의 관측 출력과 식별자 보존까지 진행합니다. 액션 송신·사이클 상태는 구현하지 않습니다.
- **근거:** 계획서 §2.1, A §3·§12, B §3·§15, B 상세설계 §15.4, C 상세설계 §16.8.5. 액션 필드 상세는 C 상세설계 §16.8.5가 기준이며 이 문서에서 새로 정하지 않습니다.

## 4. C에게 요청 (7건)

C의 회신은 Gazebo 카메라 입력 연동과 분류 실행 경계(C-06·C-07)의 일정에 필요합니다. 도착·접촉 등 실행 피드백은 C 소유라 A가 입력으로 구현하지 않습니다(C-02 폐기). **월드·녹화 확보는 저장 입력용 공통 자료형 구현의 선행조건이 아닙니다.** 공통 자료형과 저장 입력 작업은 공개 저장 자료로 먼저 진행합니다.

### C-01 Gazebo 카메라 토픽·광학 프레임·브리지

- **배경:** CameraInfo(카메라 보정 정보)와 광학 프레임(카메라 좌표계) 이름이 실제와 다르면 A의 ROS 입력이 영상을 받지 못하거나 B가 잘못된 좌표계로 계산합니다. 현재 월드의 `appearance_check_cam`은 D의 외형 확인용이며 운영 카메라가 아닙니다.
- **확인할 내용:** 운영 카메라의 `Image`·`CameraInfo` 토픽 이름, `optical_frame_id`, `ros_gz_bridge` 구성의 실제(또는 제안) 값과 준비 담당·날짜. 이 중 C가 제공·확정할 항목.
- **제안 기한:** 4일차 연동 전(설계상 1주차 합의는 유지).
- **미회신 영향:** 저장 영상 입력을 진행하고, 스마트폰은 어댑터·설정 형식만 준비합니다. ROS 입력 어댑터는 토픽 이름을 설정값으로 두고 실연동 미완료로 기록합니다.
- **근거:** A §12, 계획서 §2.2, C §8.1. (원본 §4.5 C 요청 2)

### C-02 도착 감지·접촉 센서 (0.3 폐기·통합)

- **상태:** 0.3(2026-11-11)에서 **폐기**했습니다. 사용자 확정 경계에 따라 도착 확인·접촉/비접촉·부착·보유 등 실행 피드백의 구성·수신·판정과 필요한 센서 설정은 C 소유이며, A는 도착·접촉 입력을 구현하지 않습니다([계획서 §2.6.2](../architecture/시스템_아키텍처_및_프로젝트_계획.md), [C 상세설계 §16.7.4·§16.11](C담당_로봇서버_상세설계.md)). 번호 C-02는 다른 요청에 다시 쓰지 않습니다.
- **통합처:** A·B가 재검출에 필요로 하는 C의 정지 확인 결과(`stopped_at`·벨트 이동량)·시각 기준·작업 식별자는 C-06(작업 식별자·goal 송신 활성화)과 C-07(정지 후 재검출 왕복)에서 확인합니다. 0.1 요청의 내용(메시지 형식·부품 풀 ID·시각·주기)은 A의 입력 구현용 확인으로는 더 이상 요청하지 않습니다.
- **원래 근거:** 원본 §4.5 C 요청 4.

### C-03 시각 기준·되감기·단절

- **배경:** 시뮬레이션 시간과 PC 수신 시각을 섞어 빼면 지연·유효 시간이 틀리고, 일시정지·되감기 뒤 옛 영상이 새 결과처럼 쓰일 수 있습니다.
- **A 제안(문서상 규칙):** `SIM_TIME`·ROS 원본 stamp와 PC 수신 단조 시각을 따로 보관하고, 시간 되감기는 세대 증가로 처리합니다.
- **확인할 내용:** C가 제공하는 시각 필드·기준, 일시정지·되감기·브리지 단절 때 C가 기대하는 A의 표시·무효화. 이 규칙이 C의 Gazebo·서버 운용과 맞는지.
- **제안 기한:** 4일차 연동 전.
- **미회신 영향:** A 규칙대로 두 시각 분리·세대 증가를 구현 대상으로 두고, C 기대와 다르면 재조정합니다.
- **근거:** A §5.1 「시각 관계」·§5.4, 계획서 §2.2. 공통 자료형 초안 §4 불변조건 3·4. (원본 §4.5 C 요청 1)

### C-04 월드 완료 시점과 녹화

- **배경:** 녹화는 C 월드 구성 완료 후 확보합니다(사용자 확정, 고정 기한 아님). 완료 시점을 알아야 A의 수신 확인 일정을 잡고 연동 지연 위험을 기록할 수 있습니다.
- **확인할 내용:** 월드 완료 예정 시점, 완료 후 녹화(rosbag 등) 제공 시점·형식(토픽 목록·길이)·전달 경로.
- **제안 기한:** 월드 완료 예정 시점 회신은 3일차 중. 녹화는 월드 완료 후.
- **미회신 영향:** 공개 저장 이미지로 계속 진행합니다. 녹화를 받으면 A가 수신·디코딩·검출을 확인합니다. 공통 자료형·저장 입력 구현은 이 회신을 기다리지 않습니다.
- **근거:** C §11 1주차, 계획서 §5(1주차). (원본 §4.5 C 요청 3)

### C-05 카메라 Hz·RTF 측정 조건

- **배경:** C의 카메라 Hz·RTF(시뮬레이션 실시간 비율) 측정과 A의 수신률 측정 조건이 다르면 비교할 수 없습니다.
- **확인할 내용:** C의 측정 조건(해상도·갱신률·렌더링 방식), 결과 기록 위치, 공유 시점.
- **제안 기한:** 4일차 연동 전.
- **미회신 영향:** A는 자체 수신률만 기록하고 C 결과와의 대조는 기다립니다.
- **근거:** C §8.1·§12, 계획서 §5 완료 기준.

### C-06 분류 시작·정지에 따른 파이프라인 활성화와 작업 식별자 (0.2 추가)

- **배경:** GUI가 `START`를 보내면 C가 준비를 확인하고 A/B 파이프라인을 활성화해 A 검출 → B 계산 → B→C 액션 목표 → C 실행이 이어집니다(사용자 확정). A/B가 언제 목표를 보내고 언제 멈추는지, 어떤 작업·세대에 속한 목표인지 C와 같은 기준이어야 합니다.
- **A 제안:** C가 START 수락 뒤 파이프라인의 분류 goal 송신을 켜고 STOP·정지 종료·복구 잠금 때 끕니다. A의 검출·표시와 수동 이동용 관측은 이와 무관하게 계속 동작합니다(사용자 확정 순서에 더한 제안, B 상세설계 §15.4). goal에는 C가 발급한 `sort_job_id`와 B가 쓴 `run_epoch`를 실어 C가 현재 작업·세대와 대조합니다(C 상세설계 §16.5.2·§16.8.5).
- **확인할 내용:** C가 활성화·비활성화를 파이프라인에 알리는 내부 경로(미결, C 상세설계 §16.11. A→B 사이에는 ROS 인터페이스를 만들지 않음), 파이프라인이 `sort_job_id`·`run_epoch`를 받는 시점과 방법, 활성화가 늦거나 끊겼을 때 A/B가 보일 상태.
- **제안 기한:** 2주차 통합 전.
- **미회신 영향:** A는 활성화 여부와 관계없이 관측 출력만 진행하고, goal 송신 조건은 B·C 결정 뒤 연결합니다.
- **근거:** C 상세설계 §16.5.2·§16.8.4·§16.8.5·§16.11, B 상세설계 §15.4, TCP 명세서 부록 A(GUI 명령은 단일 TCP 경로).

### C-07 정지 후 재검출 왕복과 실패·복구 뒤 결과 폐기 (0.2 추가)

- **배경:** 볼트는 벨트를 멈춘 뒤 정지 후 프레임으로 다시 검출해 집습니다. C의 정지 확인 결과가 A 재검출의 시작 조건이 되고, 실패·격리·복구 뒤에는 이전 사이클의 결과를 쓰면 안 됩니다.
- **A 제안:** B 상세설계 §15.4·C 상세설계 §16.8.5의 제안을 따릅니다. `STOP_FOR_PICK` result(`stopped_at`·`belt_travel_m`)를 받은 뒤 `stopped_at` 이후 프레임만 재검출하고, 정지 전후는 같은 처리 세대(`generation`)여야 하며 바뀌면 `ABORT_CYCLE`. 사이클이 격리·실패로 끝나 부모 분류 작업이 정지 종료되거나 `RECOVER`·`run_epoch` 변경이 있으면, A/B는 그 전 사이클의 관측·목표를 새 작업에 쓰지 않습니다.
- **확인할 내용:** C의 정지 확인 시각 기준(`SIM_TIME` 제안)과 A 프레임 시각의 대응, 저장 입력을 분류 순서 재현(replay)에 쓸 때의 시각 대응(미결), 실패·복구 뒤 A/B에 알릴 폐기 신호의 형식과 담당.
- **제안 기한:** 2주차 통합 전.
- **미회신 영향:** A는 프레임 시각·세대·`job_seq` 보존과 세대 변경 무효화(A §5.4)까지 진행합니다. 재검출 왕복 연결은 B·C 결정 뒤에 합니다.
- **근거:** B 상세설계 §15.4·계획서 §2.6.3·C 상세설계 §17.1, C 상세설계 §16.5.2·§16.8.3·§16.8.5·§16.11, A §5.4.

## 5. D에게 요청 (6건)

D의 0.1 수락(§1.1)은 같은 프로세스 GUI 전제였습니다. GUI가 Windows로 바뀌어 D-01~03·D-05·D-06은 아래 0.2 내용으로 다시 확인해 주세요. D-04는 이미 작성된 공통형을 기준으로 바꿨습니다.

### D-01 Windows GUI로의 결과·측정값 전달 (0.2 갱신)

- **배경:** A/B는 WSL, GUI는 Windows의 별도 프로세스입니다. 0.1의 "시그널·대기열로 결과 객체 전달"은 같은 프로세스 전제라 그대로 쓸 수 없습니다. 측정값(px·mm 좌표·각도·규격·유효성)이 어느 프레임·결과에 속하는지 화면에서 맞지 않으면 사용자가 옛 결과를 현재 값으로 볼 수 있습니다.
- **A 제안:** A/B 내부(같은 프로세스)의 결과 객체 전달과, Windows GUI로 보내는 **OS 간 결과 메시지**를 나눕니다. 화면 갱신은 GUI 스레드에서(0.1 수락 내용 유지). mm 변환은 D가 한 번(B §5.5). 전달 기술(별도 스트림·결과 채널 등)은 미결이며 이 요청으로 정하지 않습니다. 로봇 명령 TCP에는 영상을 넣지 않습니다(TCP 명세서 §0).
- **확인할 내용:** 결과 메시지에 실을 식별자(`run_id`·`source_id`·`image_seq`·`capture_generation`·`generation`·`job_seq`·`calibration_id`)와 측정값 필드, 직렬화 형식, 결과와 영상 프레임의 대응 방법, 늦게 온 결과의 폐기 기준(세대·유효 시간), 연결이 끊겼을 때의 화면 표시.
- **제안 기한:** 1~2주차(표시 경로 결정, A §12).
- **미회신 영향:** A는 내부 결과형과 식별자 보존까지 구현하고, Windows GUI 연결은 하지 않습니다.
- **근거:** 계획서 §2.1, A §3·§12·§12.1(결과 전달 행 재검토), D §A.2·§A.11.2, B §5.5, TCP 명세서 §0.

### D-02 버퍼 소유권과 OS 간 영상·오버레이 표시 (0.2 갱신)

- **배경:** 버퍼 수명 규칙(처리 중 영상을 덮어쓰지 않음)은 A/B 내부에서 여전히 필요합니다. 다만 Windows GUI는 WSL 프로세스의 배열을 직접 참조할 수 없으므로, 내부 버퍼 소유권과 화면 표시용 영상·오버레이 전달은 다른 문제입니다.
- **A 제안:** ① **A/B 내부:** 최신 대기 프레임 1개, 처리 중 영상 보존, 폐기 수 기록. 생산자는 넘긴 버퍼를 재사용하지 않고 소유권 양도 또는 독립 복사로 넘깁니다(0.1 수락 내용, 공통 자료형 초안 §4 불변조건 8). ② **OS 간 표시:** 영상·오버레이를 직렬화(압축 이미지·오버레이 좌표 등)해 보내고, 수신 후 표시 버퍼는 D가 관리합니다. 전달 기술은 미결입니다.
- **확인할 내용:** 표시용 영상의 해상도·압축·주기, 오버레이를 영상에 그려 보낼지 좌표로 보낼지, 영상과 오버레이·측정값의 `source_id`·`image_seq`·세대 대응, 지연된 영상·오버레이 폐기, 단절·재접속 시 표시.
- **제안 기한:** 1~2주차(표시 경로 결정).
- **미회신 영향:** ①은 제안 정책으로 계속 구현합니다. ②는 연결하지 않습니다.
- **근거:** A §3·§9·§12, 공통 자료형 초안 §4 불변조건 8, 계획서 §2.1.

### D-03 무효화 이벤트의 OS 간 전달 (0.2 갱신)

- **배경:** 세대 변경·처리 오류 뒤 이전 후보를 쓰지 못하게 하는 무효화 이벤트가 Windows GUI에 늦거나 빠지면, 사용자가 옛 후보로 수동 `MOVE`를 보낼 수 있습니다.
- **A 제안:** 처리 세대·작업 순번·원인·프레임 식별자를 전달합니다. 세대 변경도 같은 무효화 이벤트로 알리고, 프레임 없는 오류에 가짜 `image_seq`·`job_seq`를 만들지 않습니다(A §5.4 규칙 유지). 결과 메시지(D-01)와 같은 경로·순서로 보내 결과보다 먼저 오거나 뒤집히지 않게 하는 것을 제안합니다.
- **확인할 내용:** 이벤트·필드 이름, OS 간 전달 순서 보장, 입력 상태 이벤트와의 구분, 단절 중 놓친 이벤트를 재접속 뒤 어떻게 맞출지(현재 세대 조회 등), D 수신 반영(송신 전 확정 스냅샷, D §A.6).
- **제안 기한:** 1~2주차(표시 경로 결정).
- **미회신 영향:** 이벤트를 A 내부 기록으로만 남기고 GUI 전달은 기다립니다.
- **근거:** A §5.4·§12, D §A.3·§A.6. 공통 자료형 초안 §3.5·§3.6.

### D-04 공통 자료형의 변경 관리와 소비 호환 (0.2 갱신)

- **배경:** `src/eyetoarm/common/types.py`는 이미 작성돼 있습니다. 최소 공통형 `TimestampBase`·`InputStatus`·`FramePacket`(14개 필드)·`InputStatusEvent`(5개 필드)가 들어 있고, `src/eyetoarm/inputs/base.py`가 이를 상속해 A 확장(`source_ref`·`source_index`)을 붙여 씁니다. `PlanarObservation`·`WorkPlanarResult`·`CandidateInvalidationEvent` 같은 관측·결과·사건형은 아직 구현하지 않았습니다.
- **A 제안:** 이미 쓰는 최소 공통형은 공통 자료형 초안 §3 기준으로 계속 쓰고, 다시 승인 대기로 돌리지 않습니다. 앞으로의 필드 변경과 미구현 자료형 추가는 초안 §6의 변경 관리 절차(영향 담당 확인)를 따릅니다.
- **확인할 내용:** ① 기존 최소형을 B·D가 소비할 때 필드 이름·타입·필수 여부가 맞는지(소비 호환, D는 표시·소비 호환 확인), ② 미구현 관측·결과·사건형의 필드 정의 시점(B 결과형은 B가 의미·단위·유효 조건 정의). ③ 공통 파일 관리·변경 반영·호환성 확인 담당은 **A로 결정**(사용자 결정 2026-11-11, 계획서 §3)되어 회신 대상에서 뺐습니다.
- **제안 기한:** ①은 B·D가 처음 소비하기 전, ②는 각 자료형 구현 전.
- **미회신 영향:** A는 기존 공통형을 계속 쓰고, 미구현 자료형은 A 모듈 안의 제안형으로 둡니다. 공통 파일을 지우거나 다시 만들지 않습니다. 공통 파일 변경은 영향 담당 확인 뒤 A가 반영합니다.
- **근거:** `src/eyetoarm/common/types.py`, `src/eyetoarm/inputs/base.py`, A §4, 공통 자료형 초안 §2·§3·§6, 계획서 §3.

### D-05 설치 환경 (WSL A/B와 Windows D 구분, 0.2 갱신)

- **배경:** A/B 처리는 WSL, 운영 GUI는 Windows에서 실행합니다. 두 환경을 하나의 "공통 설치 환경"으로 묶으면 Windows GUI 의존성을 WSL에 중복 설치하거나, WSL 처리 환경의 버전을 GUI 쪽에 강제할 수 있습니다.
- **A 제안:** ① **WSL A/B 처리 환경:** 현재 확인된 시스템 OpenCV 4.6.0·NumPy 1.26.4(apt)를 출발점으로 제안합니다(현 PC가 곧 팀 표준은 아님). ② **Windows D GUI 환경:** PySide6 등은 D가 정하고 기록합니다. A가 WSL에 설치하지 않습니다. 두 환경이 공유하는 것은 OS 간 메시지 형식(D-01~D-03)과 TCP 규약이지 Python 패키지가 아닙니다.
- **확인할 내용:** ①의 팀 기준 버전·설치 경로(apt·pip·가상환경), ②의 Python·PySide6 버전과 저장소 체크아웃 위치, 두 환경 모두에서 쓰는 공용 코드(예: `src/eyetoarm/tcp/`)가 있다면 그 버전 범위.
- **제안 기한:** 2주차 통합 전.
- **미회신 영향:** A는 WSL 현재 환경 버전만 기록하고 재설치하지 않습니다. A의 저장 입력·검출 작업은 GUI 없이 진행하므로 이 회신이 선행조건이 아닙니다. 현재 PC의 apt OpenCV는 설치돼 있다는 사실만 확인했고, 설치 주체·경위는 확인하지 않았습니다.
- **근거:** 계획서 §2.5, A §12, `requirements.txt`.

### D-06 통신 시험에서 쓸 TCP 클라이언트 (0.2 갱신)

- **배경:** A의 통신 시험 도구는 운영 클라이언트를 중복 구현하지 않고 D 클라이언트를 재사용합니다(0.1 수락 내용). 현재 저장소에는 D의 표준 라이브러리 asyncio 클라이언트 `src/eyetoarm/tcp/client.py`의 `TcpClient`가 있으며, `connect`·`disconnect`·`query_ready`·`execute`·`cancel`·`snapshot` 함수가 보입니다. **함수가 있다는 것만 확인했고, A 시험 도구와의 호환·동작은 확인하지 않았습니다.**
- **A 제안:** 시험 도구는 WSL에서 `TcpClient`를 직접 불러 쓰는 것을 우선 검토합니다. GUI(PySide6)와 분리된 모듈만 쓰고, 장애 주입은 시험 모드에서만 합니다(TCP 명세서 §8.6).
- **확인할 내용:** 재사용해도 되는 공개 API 범위와 안정성(내부 `_` 함수 제외), 실행 조건(asyncio 이벤트 루프를 누가 돌리는지, `connect`가 루프 안에서 불려야 하는지), `EventLog` 기록 위치·형식과 시험 기록의 분리, 지원 프로토콜 버전(현재 1.1. 부록 A 개정 메시지는 미승인), WSL 시험 도구가 C 서버에 붙는 주소, 이후 변경 시 알림 방법.
- **제안 기한:** 통신 시험 도구 구현 전(2주차).
- **미회신 영향:** 통신 시험 시나리오, 입출력 어댑터 설계, 결과 집계 형식은 계속 진행합니다. `TcpClient`를 호출하는 부분만 API 확인 뒤에 연결합니다. 이번 검토로 클라이언트 API가 최종 승인된 것은 아닙니다.
- **근거:** A §2·§12, 계획서 §3 통신 시험 분담, D §A.11, `src/eyetoarm/tcp/client.py`, TCP 명세서 §8.

## 8. 범위

- 1~3주차 평면 분류의 내부 자료형·입력 계약과, A/B가 출력·소비하는 분류 실행 경계(B-07·C-06·C-07)가 대상입니다. 6D와 사람 자세는 포함하지 않습니다.

- 이 문서는 실제 발송·구현 승인을 포함하지 않습니다.
