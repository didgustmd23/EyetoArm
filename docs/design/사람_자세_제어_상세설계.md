이 문서는 설계 제안입니다. 자세 모델·매핑·제어 코드는 없으며, 모델 설치·실행·실측을 하지 않았습니다. 모델과 제어기 후보는 실제 설치 버전에서 동작을 확인하지 않았습니다.

## 1. 범위와 결정 상태

### 1.1 사용자 확정

- 4~5주차 후반 확장은 사람 자세 추정 기반 로봇 동작 제어
- 6D ArUco·PnP는 이번 5주 필수 산출물에서 후속으로 이동. 기존 TCP 1.1의 6D 정의(`POSE_6D`)와 기존 구현은 삭제·무효화하지 않음

### 1.2 미확정: 제어 방식

사용자가 아직 고르지 않았습니다.

| 방식 | 내용 | 상태 |
|---|---|---|
| **사전 동작 선택형** | 정해진 몸 자세(의도)를 인식하면 미리 정의한 로봇 동작 하나를 실행 | **기본 권장안(제안, 확정 아님)** |
| 제한된 손 위치 연속 제어 | 기준 자세 대비 손 이동량을 작은 작업 상자 안의 목표로 바꿔 계속 추종 | 후보. 5주 필수 완료로 약속하지 않음 |

| 결정 항목 | 소유 | 기한 | 미확정일 때 |
|---|---|---|---|
| 1차 범위 결정 | 사용자(팀 합의). D가 결정 기록 정리, A·B·C가 영향 검토 | 1주차 말 | 사전 동작 선택형으로 계획을 진행 |
| 착수 전 재확인 | 사용자. D가 재확인 기록 | 4주차 1일차 이전 | 사전 동작 선택형으로 착수. 연속형은 후속 또는 여유 시 실험으로만 다룸 |

## 2. 구성과 담당

| 담당 | 책임 | 하지 않는 것 |
|---|---|---|
| A | 자세 모델 실행(후보 MediaPipe Pose Landmarker, 사전학습 모델 추론 — 학습 필수 아님), 관절점(이미지 정규화 좌표·모델 world 좌표), visibility/presence 신뢰도, 프레임 시각·`image_seq`, 사람 수, 유효성·무효 사유 출력 | 로봇 명령 직접 생성 |
| B | 기준 자세 보정, 의도 판정(유지 시간·히스테리시스), 의도→사전 동작 ID 매핑(연속형이면 제한된 목표), 작업 범위·속도 제한 값, 필터 | 팔·장치 직접 제어, 실행 슬롯 관리 |
| C | 사전 동작의 계획·실행, 속도·가속도 배율, 작업 범위·관절 제한·충돌 확인, 입력 유실·오래된 입력에서 정지 판정과 정지 확인, 모드 중재 | 자동 재개 |
| D | 사용자 동의·활성화 스위치, 모드 표시, 관절점·의도 오버레이, 정지 버튼, 확장 명령 송신 | GUI 이벤트 루프에서 동작 실행 |

**좌표 주의.** 모델의 world 관절점은 사람 몸(골반 중심 등) 기준의 좌표입니다. 이를 로봇 베이스나 작업대 W의 절대 좌표로 바로 쓰지 않습니다. 사전 동작 선택형은 관절 사이의 상대 관계로 의도만 판정하고, 연속형도 기준 자세 대비 상대 이동량을 B가 제한된 범위로 바꿉니다.

## 3. 사전 동작 선택형 (기본 권장안)

1. 의도 집합(제안): 예) 오른손 들기 → 동작 P1, 왼손 들기 → P2, 양손 들기 → P3, 양팔 교차 → 정지. 실제 집합과 자세는 4주차 1일차에 B가 정함
2. 의도 확정 조건: 한 사람만 보임, 관련 관절점 신뢰도가 기준 이상, 입력이 최신, 같은 의도가 유지 시간 동안 지속
3. 의도 하나에 C 명령 하나. 동작 중에는 정지 의도·정지 버튼만 받고, 끝난 뒤 중립 자세를 확인해야 다음 의도를 받음
4. 사전 동작은 그리퍼를 움직이지 않는 팔 동작으로 한정(제안). 물체를 들고 있지 않은 상태에서만 실행

## 4. 연속형 후보 (5주 필수 아님)

기준 자세 대비 손 이동량을 작은 작업 상자 안의 끝단 목표로 바꾸고, 속도·변화량 제한과 필터를 둡니다. 활성화 스위치를 누르고 있는 동안만 추종합니다. 실제로 진행한다면 평가를 사전 동작 선택형과 따로 둡니다(§7).

## 5. 안전과 모드 배타

- 자동 분류와 사람 제어는 팔 명령을 동시에 내지 않습니다. 모드 전환은 C가 판정합니다([그리퍼·로봇 실행 상세설계 §8.3](그리퍼_확장_상세설계.md)).
- 사람 제어 진입 조건: 벨트 정지 확인, 미종료 명령·goal 없음, 보유 상태 `DETACHED` 확인, 사용자 동의와 활성화
- 보유 중(`HELD`)이거나 보유 불명(`HOLD_UNKNOWN`)이면 사람 제어에 들어가지 않습니다.
- 추적 유실·오래된 입력·여러 사람·신뢰도 저하·GUI 하트비트 타임아웃: 새 동작을 막고, **이미 수락된 동작도** C가 정지 판정(취소 요청 → goal 종료·정지 확인)합니다. 이 입력 생존성 정책은 분류 작업의 "수락 후 부품 비전 무효화는 영향 없음"·"GUI 단절은 취소 아님" 규칙보다 우선하며, `HUMAN` 동작에만 적용합니다([그리퍼·로봇 실행 상세설계 §7.6](그리퍼_확장_상세설계.md)). 자동 재개·자동 개방 없음. 사용자의 명시적 재활성화가 있어야 다시 받습니다.
- 입력 유실 판정 시간·갱신 주기는 확장 명령 계약의 타임아웃으로 D·C가 1주차에 정합니다.

## 6. 통신

사람 제어 명령(활성화·의도·비활성화·하트비트)은 TCP 1.1에 넣지 않고 [그리퍼·로봇 실행 상세설계 §8.4](그리퍼_확장_상세설계.md)의 확장 명령 계약(제안)으로 정의합니다.

## 7. 일정과 평가

| 주차 | A | B | C | D |
|---|---|---|---|---|
| 1주차 | 모델 후보 설치 가능성 조사 계획 | 제어 방식 영향 검토 | 모드 중재 구조 | 결정 기록, 계약 초안 |
| 4주차 | 모델 실행·관절점 출력·유효성 | 기준 자세·의도 판정·매핑 | 사전 동작 실행·입력 유실 정지 | 동의·활성화·모드 표시 |
| 5주차 | 반복 시험·결과 취합 | 오판정 분석 | 오류·정지 복구, 분류 회귀 | 시연 화면, 최종 발표 |

**평가 (계획·미실행).**

| 지표 | 사전 동작 선택형 | 연속형(진행 시에만, 별도) |
|---|---|---|
| 의도 인식 | 의도별 혼동표, 전체 시도 분모 | — |
| 오동작 | 의도하지 않은 명령 수(중립·무관 동작 시험 중) | 작업 상자 밖 목표 수 |
| 지연 | 자세 확정→명령 수락→동작 시작 | 손 이동→끝단 추종 지연 |
| 유실 정지 | 유실 주입 후 정지 확인까지 시간, 자동 재개 0건 | 같음 |
| 모드 배타 | 분류 중·보유 중·불명 상태 진입 거부 | 같음 |

무효·미처리 시도도 분모에 넣어 따로 집계하고, 확인자·날짜·절차·결과·증거 경로를 붙입니다.
