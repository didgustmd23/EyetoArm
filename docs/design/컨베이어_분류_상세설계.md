## 1. 범위와 결정 상태

### 1.1 사용자 확정

- 전체 5주. 3주차 중간 발표, 5주차 최종 발표
- 1~3주차는 볼트 2규격과 너트 1규격이 컨베이어로 공급되는 분류 시나리오
- 볼트는 규격별 상자 2개, 너트는 마지막 공통 상자로 배출하는 **현재 논의안**(상자 구성은 논의안이며 최종 확정 아님)
- 인식은 A, 좌표·목표 계산은 B, 로봇 실행은 C, 조작·통신·상태 표시는 D
- 최종 부품 모델: BOLT_A = M6×12, BOLT_B = M6×40(ISO 4762 육각 홈붙이 볼트), 너트 M6(ISO 4032). 두 볼트는 축 길이 12 mm / 40 mm로 구분(모델 메시 기준 머리 포함 전체 길이 약 18 / 46 mm). 너트는 설정상 맞변 10 mm·두께 5.2 mm(`simulation/models/*/model.sdf`)
- 1~3주차 분류 입력은 저장 자료·Gazebo. C 월드 녹화는 C 월드 구성 완료 후 확보하며, 그 전에는 공개 저장 이미지로 A 검출을 진행

### 1.2 미확정

| 항목 | 상태 | 결정 담당·기한 |
|---|---|---|
| 길이 판정 기준점(머리 포함 전체 길이 / 축 길이), 허용 범위, 관측면·좌표·파지 설정 | 미확정(최종 모델은 확정) | B(A 확인), 1주차 초안 → 2주차 파일럿 |
| AI 클래스 구성: 정확히 3클래스(볼트 A·볼트 B·너트)인지, `bolt`/`nut` 2클래스 + 치수 기반 규격 판정인지 | A·B 파일럿 제안 | A·B, 2주차 파일럿 후 3주차 평가 전 고정 |
| 상자 배치·크기, 벨트 속도·길이 | 미정 | B(좌표·치수)·C(모델), 1주차 |

### 1.3 5주 최소 구현안 (설계 제안, 사용자 확정 아님)

아래는 5주 안에 끝내기 위한 **우선순위 제안**이며 범위를 줄인 결과입니다.

- Gazebo의 부착 기반 집기 시연(물리 파지 아님), 2지 그리퍼 1종 고정
- 부품은 한 개씩, 겹치지 않게 공급
- 볼트: 검출 → 벨트 정지 → 실제 정지 확인 → 재검출 → 집기 → 규격별 상자로 운반·배출 → 복귀 → 벨트 재가동
- 너트: 벨트를 멈추지 않고 끝의 공통 상자로 자연 배출, 실제 도착 확인
- 실패한 볼트가 너트 상자로 흘러가지 않도록 벨트를 멈추고 격리하는 정책과 실패 집계

### 1.4 후속 범위 (이번 5주에서 축소)

그리퍼 4종 교체, 움직이는 벨트 위 연속 집기, 실물 로봇·마찰 기반 물리 파지, 6D ArUco·PnP 기반 집기, 겹침·동시 공급, 3규격 이상(우선순위 제안). 6D ArUco·PnP의 후속 이동 자체는 사용자 확정입니다. 이전 7주 계획(그리퍼 확장 2주)의 내용은 [그리퍼·로봇 실행 상세설계](그리퍼_확장_상세설계.md)의 변경 이력에 보존합니다.

## 3. 인식과 규격 판정

### 3.1 A의 출력 (제안)

부품마다 `part_track_id`(검출 구역에서 부여한 추적 ID), 클래스 후보·신뢰도, 픽셀 윤곽 또는 마스크, 프레임 정보(`image_seq`·시각·`capture_generation`), 유효성·무효 사유를 냅니다. 운영 비전 모듈은 벨트·로봇 명령을 직접 만들지 않습니다.

### 3.2 B의 판정 (제안)

- 작업 좌표 위치·장축각, 측정 치수(볼트 길이, 너트 맞변), 규격 판정(`BOLT_A`·`BOLT_B`·`NUT`·`UNRESOLVED`), 파지점, 규격별 개구폭, 목적지 상자 좌표를 냅니다.
- 판정 근거가 모호하면(치수가 두 규격 사이, 클래스와 치수 불일치) `UNRESOLVED`로 두고 C가 격리 경로로 처리합니다(§5).
- **클래스별 방향 필요 여부.** 장변/단변 1.5 조건은 볼트에만 적용합니다. 너트는 방향 없이 자연 배출하므로 이 조건으로 무효가 되지 않고(정육각 너트 비 약 1.155), θ를 내지 않습니다. 기준 표는 B 상세설계 §7.2 「클래스별 방향 필요 여부」입니다.
- **관측면 계약 재검토.** 기존의 윗면(`top_face`) 윤곽과 높이별 Homography 계약은 단일 판형 부품을 기준으로 했습니다. 볼트(머리·축이 벨트에 누운 자세)와 너트(평면이 위)에 그대로 성립한다고 보장하지 않습니다. 부품별 관측면·치수 측정 기준·파지 기준과 B의 보정 계약은 1~2주차 재검토 항목입니다(B 상세설계 §13).

## 4. 분류 순서 (C)

C의 실행 관리자가 분류 작업 하나를 단일 실행 슬롯으로 관리합니다([그리퍼·로봇 실행 상세설계 §8](그리퍼_확장_상세설계.md)). 아래 단계 이름은 제안입니다.

| 단계 | 동작 | 넘어가는 조건 |
|---|---|---|
| `RUNNING` | 벨트 가동, A의 검출 구역 감시 | 검출 구역에 유효 부품 1개 |
| 분기 | B 판정이 `NUT`이면 `NUT_PASS`, `BOLT_A`/`BOLT_B`이면 `BELT_STOP`, `UNRESOLVED`·무효(클래스별 유효성 기준, §3.2. 볼트의 `DIRECTION_UNSTABLE` 포함)면 `ISOLATE_STOP` | — |
| `NUT_PASS` | 벨트를 멈추지 않음. 그 `part_track_id`의 너트 상자 도착을 기다림 | 너트 상자 도착 확인 → 수량 +1 |
| `BELT_STOP` | 정지 구역에서 벨트 정지 명령 | 벨트 실제 속도 ≈ 0이 확인 구간 동안 유지되고 부품이 정지 |
| `REDETECT` | 정지 후 새 프레임으로 재검출·재판정(세대 갱신) | 동일 물체 연계·정지 안정성·규격 일치를 아래 기준으로 확인하고, 정지 후 위치가 집기 범위 안 |
| `TARGET` | B가 파지점·개구폭·목적지 계산 | 목표 유효, 세대 일치 |
| `PICK` | 집기(그리퍼·로봇 실행 상세설계 §7.1의 `OPEN`~`LIFT`) | `HELD` |
| `TRANSPORT` | 규격별 상자 위 배출 높이로 운반 | 팔 goal 성공, 보유 유지 |
| `DROP` | 상자 위에서 해제(§7.5 해제 순서) → 열기 | Gazebo·Scene 분리 확인 |
| `ARRIVAL` | 해당 상자 도착 확인 | 상자 도착 확인 → 수량 +1 |
| `HOME` | 복귀 자세 | 팔 정지 |
| `RESTART` | 벨트 재가동 | 벨트 속도 회복 → `RUNNING` |

- 벨트 정지 명령만으로 정지했다고 보지 않습니다. 실제 속도와 부품 정지를 확인한 뒤에만 재검출합니다.
- 정지 전 검출 결과로 집지 않습니다. 목표는 **정지 후 재검출 좌표**로 새로 계산합니다(B).
- **동일 물체 연계.** 정지 전 검출과 정지 후 재검출이 같은 부품인지는 `part_track_id`와 예상 이동으로 판정합니다. 검출 시점부터 정지까지 벨트가 이동한 거리(벨트 실제 속도 적분, C가 제공)만큼 벨트 진행 방향으로 옮겨진 위치가 예상 위치이며, 실제 위치가 예상 위치에서 허용치 안(진행 방향·가로 방향 각각)이고 장축각 변화가 허용치 안이면 같은 부품입니다. 벨트 이동에 따른 위치 변화 자체는 거부 사유가 아닙니다.
- **정지 안정성.** 정지 확인 후 연속 프레임 사이 위치·장축각 변화가 허용치 안이어야 새 좌표를 채택합니다. 흔들림이 계속되면 다시 기다리고, 시간 초과면 `REDETECT_UNSTABLE`로 격리 경로에 갑니다.
- **거부.** 예상 위치를 벗어나 다른 물체로 볼 수밖에 없거나(`REDETECT_MISMATCH`), 정지 전후 규격 판정이 다르면(`SPEC_CHANGED`) 그 결과를 쓰지 않고 `ISOLATE_STOP`으로 갑니다. 허용치 수치는 2주차 파일럿에서 B·C가 정합니다.
- **승인 범위.** 사용자는 `SORT_START`로 분류 시작을 한 번 승인합니다. 정상 사이클의 `BELT_STOP`·`RESTART`는 이 승인 아래 C가 자동 실행하며 부품마다 다시 승인하지 않습니다. 사용자 정지(`SORT_STOP`), 오류·격리(§5)·복구 이후에는 벨트를 멈춘 채 두고, 사용자가 재개를 명시적으로 확정해야 `RUNNING`으로 돌아갑니다. 사용자 정지를 자동 재개하지 않습니다.
- 운반 중이나 해제 직후에도 벨트는 멈춘 채로 둡니다. 다음 부품이 검출 구역에 들어오기 전에 재가동하지 않도록 공급 간격을 파일럿에서 정합니다.

## 5. 실패와 격리

실패한 볼트가 너트 상자로 흘러가지 않게 하는 것이 우선입니다. 볼트·미판정 부품에 관련된 실패에서는 벨트를 멈춘 채로 두고, 자동 재가동·자동 재집기·자동 개방을 하지 않습니다.

| 상황 | 판정(제안) | 처리 |
|---|---|---|
| 검출 구역 통과 후 검출 없음 | `MISSED_DETECTION` | 너트 상자에 검출 기록 없는 물체가 도착하면 벨트 정지, 이상 기록 |
| 규격 미판정·클래스/치수 불일치 | `UNRESOLVED` | `ISOLATE_STOP`: 벨트 정지 → 사용자 확인 후 격리 |
| 벨트 정지 미확인 | `BELT_STOP_UNCONFIRMED` | 집기 금지, 벨트 정지 명령 유지, 사용자 복구 |
| 재검출 불일치(다른 물체·규격 변경·정지 불안정) | `REDETECT_MISMATCH`·`SPEC_CHANGED`·`REDETECT_UNSTABLE` | 집기 금지 → `ISOLATE_STOP`. 예상 범위 안의 벨트 이동은 해당 없음 |
| 집기 실패(빈 집기·조건 불일치·부착 불명 등) | 그리퍼·로봇 실행 상세설계 §7.6 | 벨트 정지 유지. 보유 상태별 다음 작업은 같은 문서 §8.3 |
| 운반 중 보유 상실 | `HOLD_LOST` | 벨트 정지 유지, 물체 위치 기록, 사용자 복구 |
| 상자 도착 미확인 | `ARRIVAL_UNCONFIRMED` | 수량 증가 없음, 벨트 정지 유지, 사용자 확인 |
| 너트 상자에 볼트·미판정 물체 도착 | `WRONG_BIN` | 벨트 정지, 실패 집계 |

**격리 절차(`ISOLATE`).** 사용자가 확정한 명시 작업으로만 실행하며, 시작 조건은 보유 `DETACHED`·잠금 없음입니다(그리퍼·로봇 실행 상세설계 §8.3).

1. 보유 상태가 `HOLD_UNKNOWN`이거나 `RECOVERY_REQUIRED`로 잠겨 있으면 격리·배치 이동을 하지 않고, 먼저 사용자가 확정한 `RECOVER`(같은 문서 §4.3)로 분리·정지와 초기화를 확인합니다. 결합이 남아 있을 수 있는 상태에서 물체를 배치 이동으로 옮기지 않습니다.
2. `RECOVER`의 재기동으로 부품이 초기 배치(대기 구역)로 돌아가면 그 부품은 **실패(복구 회수)**로 기록하며 분류 성공으로 세지 않습니다. 벨트 위에 남은 부품이 있으면 3으로 갑니다.
3. `DETACHED`에서 로봇이 집을 수 있으면 격리 구역으로 옮기고, 집을 수 없으면 비접촉 확인 후 배치 이동(같은 문서 §7.7 3과 같은 조건)으로 옮깁니다. 격리된 부품은 실패로 집계합니다.
4. 격리·회수가 기록된 뒤 사용자가 재가동을 확정해야 `RUNNING`으로 돌아갑니다.

### 5.1 검증 시나리오 (계획·미실행)

| 시나리오 | 기대 결과 |
|---|---|
| 검출 후 정지까지 벨트가 예상 거리만큼 이동한 같은 볼트 | 같은 부품으로 연계, 정지 후 새 좌표로 목표 계산, 정상 집기 |
| 예상 위치 밖의 다른 물체가 정지 구역에 있음 | `REDETECT_MISMATCH`, 집기 0건, 격리 경로 |
| 정지 전 `BOLT_A`, 정지 후 `BOLT_B` 판정 | `SPEC_CHANGED`, 집기 0건 |
| 정지 후 흔들림 지속 | 대기 후 시간 초과 시 `REDETECT_UNSTABLE` |
| `ATTACH_UNCONFIRMED` 후 `ISOLATE` 요청 | 거부(`HOLD_UNKNOWN`), 확정한 `RECOVER` 후에만 격리. 복구 회수는 실패로 집계 |
| 너트 상자에 볼트 도착 주입 | `WRONG_BIN`, 벨트 정지 |
| 정상 너트(종횡비 약 1.155) | 방향 조건으로 무효가 되지 않고 `NUT`, `NUT_PASS` → 너트 상자 도착 확인 |
| 종횡비 1.5 미만으로 측정된 볼트(방향 불안정) | `DIRECTION_UNSTABLE`로 무효, 집기 0건, `ISOLATE_STOP` |
| 시작 승인 후 정상 볼트 2개 연속 공급 | 첫 볼트의 `BELT_STOP`·집기·배출·`RESTART`와 두 번째 볼트 처리가 추가 사용자 승인 없이 진행 |
| 오류(예: `REDETECT_MISMATCH`)·사용자 정지 후 | 벨트 정지 유지, 사용자 확정 전 재가동 0건. 확정 후에만 `RUNNING` |

## 6. 수량 집계와 표시

- 상자별 수량은 **도착 확인 이벤트**로만 올립니다. 명령 송신·해제 요청·운반 완료로 세지 않습니다.
- 한 `part_track_id`는 한 번만 셉니다(중복 방지). 도착 확인된 물체와 분류 작업 기록의 규격이 다르면 `WRONG_BIN`으로 집계합니다.
- D는 상자별 수량, 격리 수, 실패 사유별 수, 벨트·그리퍼·로봇 상태를 표시합니다(D 상세설계 §A.11).

## 7. 통신

벨트·분류·모드 명령과 상태는 TCP 1.1에 넣지 않고 [그리퍼·로봇 실행 상세설계 §8.4](그리퍼_확장_상세설계.md)의 확장 명령 계약(제안)으로 정의합니다. TCP 1.1의 `MOVE`/`REACHED`를 집기·분류 완료의 의미로 쓰지 않습니다.

## 8. 일정 (1~3주차)

| 주차 | A | B | C | D |
|---|---|---|---|---|
| 1주차 | 카메라·도착 감지 입력 구성, 볼트/너트 촬영·데이터 수집 계획, 클래스 구성 후보 | 최종 부품 치수 확인, 길이 판정 기준점·허용 범위 초안, 벨트·상자·격리 좌표 | 벨트·부품·상자 모델 골격과 벨트 제어 확인, 기존 TCP 서버 골격, 실행 관리자 구조 | GUI 모드·벨트·수량 화면 골격, 확장 명령 계약 초안(C와) |
| 2주차 | 볼트/너트 검출·라벨·학습, 추적 ID, 재검출 | 규격 판정·파지점·개구폭·목적지 계산 | 벨트 정지·재가동, 집기·운반·배출, 분류 순서 1차 | 상태·수량·실패 표시, 확장 계약 클라이언트 |
| 3주차 | 분류 시험 실행·결과 취합, AI/OpenCV 비교 기록 | 규격 판정 정확도·위치 오차 평가 | 분류 반복·실패 격리·복구, 실행본 고정 | 시연 화면, 중간 발표 자료 |

3주차 말에 분류 실행본을 보존하고 중간 발표에 씁니다. 분류가 끝나지 않으면 지연·미완료를 기록하고 범위와 우선순위를 다시 정합니다(계획서 §12).

## 9. 평가 (계획·미실행)

| 지표 | 정의 |
|---|---|
| 분류 정확도 | 공급한 전체 부품 대비 맞는 상자에 도착 확인된 수. 분모는 공급 순서표의 전체 공급 수 |
| 볼트 규격별 정밀도·재현율 | `BOLT_A`·`BOLT_B` 각각. 공급 순서표(독립 정답) 기준 |
| 실제 상자 투입 | 집기 성공 중 해당 상자 도착 확인 비율 |
| 누락·중복 | 검출 없이 통과한 수, 같은 부품 중복 집계 수 |
| 너트 도착 | 공급 너트 중 너트 상자 도착 확인 비율 |
| 처리 시간 | 부품별 검출→도착 확인, 볼트의 정지→재가동 시간. 구간을 나눠 기록 |
| 정지·복구 | 실패 유형별 벨트 정지 성공, 격리·재가동까지 시간, 실패 볼트의 너트 상자 유입 수(목표 0) |

무효·미처리(격리·사용자 중단) 시도는 분모에서 빼지 않고 따로 집계합니다. 모든 결과에 확인자·날짜·절차·결과·증거 경로를 붙이고 실행 전에는 계획/미실행으로 표시합니다.
