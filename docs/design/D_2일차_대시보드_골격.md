# D 2일차 대시보드 골격 — 스테이징 구현 기준

갱신: 2026-11-13 · v0.9 · 기준: HEAD ce5531e 위 index의 D 클라이언트 9개 모듈과 시험 1개. 이 절이 현재 상태이며, v0.9는 「현재 화면 구조」 절 추가다. 아래 v0.1~v0.7은 당시 설계·HTML 시안 기록이다.

## 현재 구현과 남은 범위

Eye To Arms는 Windows/PySide6 네이티브 GUI로 구현되어 있다. 좌측 232px 사이드 카테고리는 조작·설정 / 운영 대시보드 / 평가·기록의 세 화면이다. 공통 상태 연결과 영상 수신기를 공유하며, 메인 디스플레이·우측 보조 영상 두 자리·측정/보정 상세 팝업을 둔다. 보조 영상과 실제 측정·보정·분류 수량은 아직 연결되지 않았으며 미확인 값은 — 또는 미연결 사유로 표시한다.

- 명령 연결: config/gui/client.json을 읽는 비동기 StatusLink, 기본 127.0.0.1:47090. 무ID GET_STATUS 준비 조회·연결 감시·재접속까지 구현되어 있다. MOVE/CANCEL은 3일차, START/STOP/RECOVER는 계약·후속 구현 대기다. 이 버튼들은 미전송 상태이며 로봇을 움직이지 않는다.
- 메인 표시: 기본은 Windows에 떠 있는 Gazebo 창을 GzWindowCapture로 캡처한다. --view camera는 WSL의 D 임시 카메라 중계 127.0.0.1:47091을 받는다. 외형 확인용 /appearance_check/image 경로이며 정식 A/B→C→D 표시 연결을 대체하지 않는다. C 표시 계약/부록 B 확인과 6일차 동기·무효화 검증 관문은 남아 있다.
- 기록: 메모리 TX/RX/EV 표와 전체/TX 보냄/RX 받음/EV 연결 사건 필터, 화면 비우기, 원문 툴팁이 있다. 파일 로그·CSV 내보내기는 아직 없다.
- HTML 한정 기능: 전체/메인/2번/3번 단독 확대 탭, 원본/OpenCV/좌표값/통합 회전 다이얼, 실행/TCP/오류 카테고리, 스낵바, 키보드 도움말 툴팁, CSV 원형 진행은 네이티브 이식 미완료다. 네이티브 raw/detect/center 표시는 현재 비활성이며 통합 처리 기능이 아니다.

## 현재 화면 구조 (네이티브, window.py 기준)

v0.9에서 추가. 아래 보존 이력의 「화면 구조」는 HTML 시안 배치이며, 실제 창은 이 절을 따른다.

```text
┌ 좌측 사이드 232px ┬ 제목줄: 화면 이름 │ [START 시작][STOP 분류 정지][RECOVER 복구][CANCEL 수동 이동 취소] (전부 비활성)
│ Eye To Arms       ├ 상태띠 6칸: 명령 TCP / 표시 연결 / 유효 STATUS / 로봇 준비 / 분류 상태 / 마지막 수신
│ [조작·설정]       ├ 화면 영역 (세 화면 중 하나. 메인 디스플레이는 창에 하나이며 화면 사이를 옮겨 다닌다)
│ [운영 대시보드]   │
│ [평가·기록]       │
│ 출처 꼬리표       │
│ [다크][라이트]    │
│ □ 모션 줄이기     │
└───────────────────┴──────────────────────────────────────────────
```

| 화면 | 실제 배치 | 값의 상태 |
|---|---|---|
| 조작·설정 | 영상 카드(메인 디스플레이 + 링크 채널 raw/detect/center 버튼) · 연결 · 명령 계약 상태 · 입력·보정 · 명령 목표 · 로봇 외형 | 연결 카드만 실제 값(client.json). 링크 채널 버튼은 비활성, 나머지는 — |
| 운영 대시보드(시작 화면) | 「측정·보정 상세」 버튼 + 메인 디스플레이(안쪽 오른쪽에 그리퍼·고정 보조 영상 2칸, 왼쪽 위에 상세 팝업) / 아래 카드 4개: 현재 측정 · 공정 단계 · 수량 · 최근 TX/RX | 메인 영상과 최근 TX/RX만 실제. 보조 2칸은 자리, 측정·단계·수량은 — |
| 평가·기록 | TX/RX 기록(전체/TX 보냄/RX 받음/EV 연결 사건, 화면 비우기) · 평가 · 오류 상세 | 기록 표만 실제. 평가는 —, 오류 상세는 3일차 |

- 공정 단계 표시는 볼트 4칸(정지·재검출 / 집기 / 도착 / 복귀)과 너트 2칸(통과 / 도착)이다. HTML 시안의 무효→격리 분기, 검출 방식·규격, 보유·적용, 실패 사유별 수는 네이티브에 자리가 없다. 수량 카드에는 볼트 A/B 상자·너트 상자·격리 4줄만 있다.
- 상태띠 「표시 연결」은 D 임시 경로(Gazebo 창 캡처 또는 47091 중계)의 수신 상태다. 정식 C 표시 연결의 상태가 아니다. 「분류 상태」는 항상 「— 계약 미승인」이다.
- 사이드 버튼은 Ctrl+1~3 단축키로도 고른다. 테마와 모션 줄이기는 사이드 아래에 있다.
- 개발용 인자 --shot / --shot-after / --page / --popup 은 화면 저장용이며 운영 기능이 아니다.

## 네이티브 색·모션 기준

theme.py가 현재 시각 토큰의 기준이다. 다크 바탕/카드/본문은 #0A0A0B/#131315/#F4F4F5, 라이트는 #F3F3EF/#FFFFFF/#121214다. 강조 면은 #D1FE17이며 라이트 강조 글자는 #4F6B00이다. 영상 영역은 항상 #060607로 유지한다. Segoe UI Variable Display → Segoe UI → Malgun Gothic 순서, 카드 반경 18px를 사용한다. 이전 Midnight Navy/Emerald/paper·amber는 아래 HTML 시안 이력으로만 보존한다.

모션 시간은 탐색 160ms, 팝업 180ms, 단계 200ms, 강조 240ms, 화면 등장 220ms, 순차 등장 간격 45ms다. --no-motion으로 축소하여 시작할 수 있다. 실제 프레임률·배율·키보드 접근성 통과를 뜻하지 않는다.

## 실행 안내와 확인 범위

프로젝트 루트의 기존 eyetoarm 환경에서 PowerShell로 실행한다.

```powershell
$env:PYTHONPATH = 'src'
python -m eyetoarm.d_client.window --demo --theme light
python -m eyetoarm.d_client.window --demo --no-motion
```

--demo는 소켓을 열지 않는다. 다음 명령은 실제 GET_STATUS 연결과 캡처/영상 수신을 시작하므로 모의 실행과 구분한다. 이번 문서 갱신에서는 실행하지 않았다.

```powershell
python -m eyetoarm.d_client.window
python -m eyetoarm.d_client.window --view camera
```

카메라 모드는 WSL에서 ROS/Gazebo 브리지와 gz_view_relay.py를 별도로 준비해야 한다. 정확한 순서는 해당 모듈 docstring을 따른다. --theme 생략 시 QSettings의 이전 선택(없으면 dark)을 사용하며 CLI에서 지정한 테마는 저장하지 않는다. 기본 창 1440×960, 최소 1180×760이다. 과거 HTML의 375px 반응형 시험을 네이티브 결과로 옮기지 않는다.

직전 index 대조에서 10개 파일의 작업트리/index 내용 동일·구문 검사 통과·단위시험 6개 통과를 확인했다. 이 6개는 실제 창·탭·연결 유지·접근성·C/Gazebo를 시험하지 않는다. 이번 갱신의 검증은 문서와 index 대조이며 제품 코드 시험을 재실행하지 않는다.

## 목적과 완료 범위

Windows 분류 운영자가 영상·측정·로봇 준비·분류 진행·통신 오류를 한 화면 흐름으로 파악하게 한다. 기존 D 상세설계와 1일차 진단을 기준으로 세 탭을 구성한다. 이번 산출물은 이 문서와 옆의 HTML 화면 목업이다. HTML에는 details 기반 팝업 펼침/접힘과 열릴 때 짧은 CSS 모션 예시만 있으며 실제 운영 GUI·영상·통신 데이터는 없다. 브라우저 실제 동작은 아직 검증하지 않았다.

2일차 구현 제안 범위는 PySide6 창, 공통 상태를 공유하는 세 탭, 영상 자리 3개, 모의 상태 예제, 사용자가 조작하는 짧은 모션이다. 실제 C 연결·MOVE/CANCEL·분류 명령·영상 수신·CSV는 해당 후속 일차에서 구현한다. 기존 gui/tcp/pendant와 1일차 CLI를 보존한다. RAG/LangChain은 불필요하다.

## 확인된 사실과 미결

- 현재 사용자 설치 경로를 my-skills 목록 스크립트로 조회했다. 아래 7종은 개인 설치·비활성 아님·지침 읽기 가능 상태다. 설치 목록과 서비스/렌더 실행 검증을 구분한다.
- 기존 eyetoarm Python 환경에서 PySide6 6.12.0과 QPropertyAnimation/QVariantAnimation/QParallelAnimationGroup import를 재확인했다. 창 표시·실제 모션 성능은 아직 미검증이다.
- 기존 src/eyetoarm/gui/motion.py에 fade/stagger/spring 등이 있다. 기존 코드와 테마의 결합을 읽었으며 무조건 가져오거나 기존 시험 GUI를 수정하지 않는다. 구현 시 재사용 가능 범위를 먼저 확인한다.
- models.ProbeResult는 단발 진단 결과형이며 운영 GUI 전체 상태형이 아니다. diag.probe는 GUI 이벤트 루프에서 직접 호출하지 않는다.
- C 표시 연결의 방식·포트·직렬화와 분류 명령 계약은 미승인이다. 부록 B에는 stamp_ns(SIM_TIME) 대응 초안이 이미 있으며 C/D 확인 대상이다. A 내부 image_seq/generation/job_seq와 C run_epoch를 서로 같은 키로 취급하지 않는다. 미결 필드에 가짜 실시간 값을 채우지 않는다.
- 기존 일일계획의 'd_client에는 README/environment만 존재' 및 '구현 미착수' 문구는 작성 당시 기록이다. 현재 1일차 소스·시험·기록이 존재하므로 최신 기준은 1일차 검증 문서와 현재 파일이다.

## 화면 구조

표시 이름은 Eye To Arms로 한다. 좌측 사이드에 브랜드와 조작·설정/운영 대시보드/평가·기록의 세 카테고리를 세로 배치한다. 공통 상단에는 현재 화면 이름, 데이터 출처(모의/실제), 분류 START·STOP·RECOVER와 수동 이동 취소(CANCEL) 자리를 둔다. 분류 STOP과 수동 CANCEL의 대상·효과를 구분한다. 아래 상태띠는 명령 TCP / 표시 연결 / 유효 STATUS / robot_ready / 분류 작업 상태 / 마지막 수신 경과를 각각 분리한다. 정지 조작은 팝업·모션에 가리지 않고 미연결·계약 미승인 시 미전송 사유를 표시한다.

2026-11-13 사용자 화면 방향: 메인 디스플레이 위에 팝업을 올리고 우측으로 밀착한 두 화면을 둔다. 메인은 링크 영상, 우측 두 화면은 그리퍼·고정 영상으로 해석한 시안이다. 메인 영상이 큰 바탕이고 두 보조 영상은 그 위 오른쪽 내부 가장자리에 세로로 고정한다. 팝업은 중앙~왼쪽에 배치하고 화면 내부 영역만 차지한다. 팝업 용도는 측정/보정 상세를 우선 제안하며 모든 설정을 자동으로 팝업화하지 않는다. 정지·핵심 상태띠는 위에 고정하고 측정 요약은 아래에 둔다.

```text
Eye To Arms 사이드: [조작·설정] [운영 대시보드] [평가·기록] (세로)
현재 화면: 운영 대시보드 / 모의 데이터
[START 시작] [STOP 분류 정지] [RECOVER 복구] [CANCEL 수동 이동 취소]
명령 TCP / 표시 연결 / 로봇 준비 / 분류 상태 (모두 별도)
┌───────────────────────────────────────────────┬──────────────────┐
│ 링크 영상: 원본 / 검출 / 중심점                │ 그리퍼 보조 영상 │
│                                               │                  │
│        ┌─────────────────────┐                ├──────────────────┤
│        │ 측정·보정 상세 팝업  │                │ 고정 보조 영상   │
│        │ 화면 위에 겹쳐 표시 │                │                  │
│        └─────────────────────┘                │                  │
├───────────────────────────────────────────────┴──────────────────┤
│ 현재 측정 / 검출 방식·규격 / 보정 / 보유·적용 / 허용·거부 사유    │
│ 볼트: 정지·재검출→집기→도착→복귀 / 너트: 통과→도착 / 무효: 격리 │
│ 상자별 수량 / 격리 수 / 실패 사유별 수 / 최근 TX/RX               │
└──────────────────────────────────────────────────────────────────┘
```

- 조작·설정: GUI-01~04를 함께 배치한다. 영상 3개, px/mm/θ, TX/RX, 보정 상태·적용 사유를 유지하고 입력 설정·명령 목표·외형 자산 정보를 둔다. 후속 명령은 준비 조건과 승인된 계약이 갖춰져야 활성화한다.
- 운영 대시보드: 위 배치. 공정 단계 표시기는 C의 확인된 단계만 강조하며, 시안에서는 모두 미확인으로 둔다. 명령 접수만으로 단계나 수량을 진행시키지 않는다.
- 평가·기록: TX/RX 전체 기록·필터·오류 상세·평가 자리. 정답/관측 없는 지연·정확도·성공률은 —로 표시한다. 화면 비우기는 원본 파일 삭제와 구분한다.

## 모션그래픽 규칙

중심 모션은 '현재 공정 단계의 변화'다. 2일차는 선택/모의 예제에서만 시연하고, 실제 운영에서는 검증된 사건에 연결한다. 상태 문구·수치·안전 조작 갱신을 모션 완료까지 지연하지 않는다.

| 요소 | 동작 제안 | 발동·제약 |
|---|---|---|
| 탭 선택선 | 160ms 이동, 본문은 즉시 갱신 | 사용자 탭 전환, 데이터/연결 유지 |
| 상세 영역 | 180ms 펼침·접힘 | 사용자 조작, 빠른 재입력 시 이전 애니메이션 정리 |
| 공정 단계 | 현재 단계의 강조 200ms 전환 | 확인된 새 단계만. 가상 로봇 관절 움직임으로 해석하지 않음 |
| 새로운 수량 | 확정 숫자 즉시 반영, 바탕만 240ms 강조 | C의 실제 도착 확인 후, 숫자 카운트업으로 중간값 생성하지 않음 |
| 알림·단절 | 사유 즉시 노출, 선택적 120ms 바탕 전환 | 정지 확인으로 오인 금지, 깜박임/반복 펄스 없음 |
| 모션 줄이기 | 움직임 없이 최종 상태 즉시 표시 | OS 설정 연동 가능 범위 확인 + 앱 내부 선택, OS 설정 변경 금지 |

좌표·각도·영상·시간·원시 로그는 실제 값 그대로 표시한다. 애니메이션용 보간으로 측정값을 만들어내지 않는다. 송수신 시각과 실제 로봇 운동을 장식 애니메이션 시간과 혼합하지 않는다. 가려진 탭/창 종료 시 해당 모션을 정리한다.

## 데이터·파일 경계

파이프라인: 모의/저장 예제 → 앱 공통 표시 상태 → 세 탭 → 선택적 모션. 후속 실제 연결은 명령 TCP 상태 및 별도 영상·결과·무효화 수신 → 계약 검증·순서·대응 검사 → 공통 상태 → 화면이다. 탭마다 소켓을 생성하지 않는다. 1일차 API를 보존한다. 저장 VIDEO_POS는 벨트 분류 입력이 아니다. B 내부 m→D 표시/TCP mm는 경계에서 한 번만 변환한다.

구현 시 파일 후보: d_client/window.py(창·탭·레이아웃), 필요한 경우 d_client/motion.py(공통 모션만), 단위 GUI 시험 1개, docs/gui-impl의 2일차 기록. 전용 실행 진입점은 1일차 __main__.py CLI를 깨지 않는 방식을 먼저 선택한다. 새 파일 수는 책임이 실제로 필요할 때만 늘린다. fixture는 테스트 또는 같은 모듈의 작은 상수로 시작하고 새 모의 서버/설정 체계를 만들지 않는다.

## 파이프라인·마일스톤·검증

| 단계 | 산출물·담당 | 통과 조건 | 예상 집중 작업 |
|---|---|---|---|
| 현재 설계 | 메인: 초안/시안, reviewer: 읽기 전용 요구·모션 검토 | 범위·레이아웃·미결을 사용자 검토 | 작성 완료 |
| 승인 후 골격 | 구현 담당: Windows 세 탭과 공통 상태 | 실행/종료·탭 전환·화면 크기 변경 | 2~3시간 |
| 모의 상태·모션 | 구현 담당: 정상/미준비/단절/무효 예제 | 모의 표시, 상태 유지, 즉시 정지 사유·무효화 | 2~3시간 |

위 5~8시간은 승인 후 2일차 작업의 추정이며 실행 환경·피드백에 따라 달라진다. 목표는 화면 반응이 막히지 않는 골격이며 60fps·응답시간을 검증 없이 보장하지 않는다. 화면 전환의 실제 지연과 GUI 스레드 정지를 구현 후 측정한다. 신규 복잡한 상태/모션에는 작은 의미 있는 위젯 시험을 남기고 1일차 43건은 새로 재실행한 결과와 구분한다.

현재 정적 시안은 파일 존재·구조만 확인한다. PySide6 창, 애니메이션, 실제 C/Gazebo, 영상/보정 계약, 배율·스크린리더는 미실행이다. 승인 뒤 실제 창 스크린샷과 모의 상태 시험, 종료 후 task 소유 객체/프로세스 해제를 확인해야 2일차 구현 완료다.

## 승인할 범위·보호 경계

승인 제안 v0.1: 기존 Windows/PySide6와 Qt 모션을 사용한 모의 GUI 골격, 세 탭/영상 자리/상태/기록/모션 축소 구현·검증. 외부 서비스 비용 0, 새 의존성 0, 외부 업로드 0. 실제 로봇 명령·C 서버 변경·방화벽·설치·커밋/푸시·배포는 제외한다. 승인은 아직 기록되지 않았다. 승인되면 사용자·시각·근거·범위와 후속 변경분을 이 프로젝트 기록에 추가한다.

A/B/C·공통형·원본 자산·프로파일·로그·기존 CLI를 보존한다. 정지는 전송/접수/확인을 구분하고 미확인 상태를 정지 완료로 바꾸지 않는다. 이번 문서 작성은 전경 조회만 사용했고 상시 서버/커널/렌더러/임시 파일을 만들지 않았다. 읽기 전용 reviewer는 완료했으며 Claude/공유 자원에 관여하지 않았다.

## v0.3 아키텍처 보완·사용자 배치 반영

이 절은 앞선 간략 요약보다 우선한다. [누락 대조표 R01~R12](../gui-impl/D_2일차_아키텍처_누락검토.md)의 요구사항과 단계별 책임을 계획에 연결한다. 아키텍처와 규약 원문은 바꾸지 않았다. 원격 main4a43cc9와 HEAD의 추적 파일 트리가 동일함을 확인했다.

- 2일차: START/STOP/RECOVER와 수동 MOVE/CANCEL의 별도 자리·대상·미전송 사유, 분류/사람 제어 하위 빈 틀(사람 제어 비활성), GUI-01~04 및 연결 설정·확정 송신 목표/ID 자리, 2지 고정·apply_state·보유/슬롯/거부 사유 자리, 모델 버전·정적 미리보기·외형 링크/원점/축/단위/출처/C 적용 대기 매핑표를 둔다. 실제 통신·CSV·영상 수신은 구현하지 않는다.
- 모의 화면에는 OpenCV/AI·제공 모델 ID·BOLT_A/B/NUT/UNRESOLVED·part_track_id·무효 사유를 표시하고, 상자 수량 외에 격리 수·실패 사유별 수·WRONG_BIN 자리를 둔다. 모든 집계 근거는 C이며 화면에서 영상으로 추정해 올리지 않는다.
- 전체 분류 흐름은 볼트 정지→정지 확인→재검출→목표→집기→운반→배출→도착→복귀→재가동, 너트 통과→도착, 무효→격리로 나눈다. 단계 이름은 제안이며 C가 보고한 상태만 반영한다. RECOVER 성공은 자동 START가 아니다.
- 3일차: 명령 스냅샷/직렬화 바이트·ID·reach_error·최초 ACK/복원 ACK/재전송/거부/미확인/REACHED/FAILED를 구분한다. UNKNOWN_COMMAND는 실행 여부 미확인이다. 재접속은 조회만 하며 새 MOVE/취소를 자동 재전송하지 않는다. 실제 클라이언트 API/이벤트/오류/로그/이벤트 루프 조건 초안을 마련한다.
- 4~5일차: 최신 C 작업별 허용/사유와 적용·보유·복구 잠금을 연결한다. HELD 중 정지/취소/조회는 유지한다. 정상 HELD의 새 작업은 해제 경로이며 HOLD_UNKNOWN/적용 실패/복구 잠금은 C 허용과 사용자 확정 복구가 필요하다. 같은 집계 범위의 part_track_id·재접속 재전달을 중복 집계하지 않는다. 부록 A 미승인이면 실제 전송 대신 모의로 검증한다.

### 팝업·우측 보조 영상의 모션·접근성

메인 링크 영상은 한 장만 두고 우측 보조 두 장은 같은 표시 영역의 오른쪽 경계에 고정한다. 팝업은 중요한 ROI·상태·보조 영상을 가리지 않는 위치를 우선하고, 실제 ROI 위치에 따라 배치 조정은 구현 때 확인한다. 메인 시야를 가리는 경우 상세 팝업을 닫고 동일 정보에 다시 접근할 수 있어야 한다.

팝업 열기/닫기에서만 160~180ms 투명도 전환을 제안한다. 영상·숫자·정지 조작은 즉시 갱신한다. 키보드로 열기/닫기, Escape, 닫힌 뒤 원래 조작으로 포커스 복귀, 배경 가림 여부에 맞는 포커스 범위를 검증한다. 모달 팝업의 포커스가 정지 조작을 막지 않도록 운영 정보는 비모달을 우선한다. 모션 줄이기는 즉시 최종 상태를 표시하고 OS 설정은 바꾸지 않는다.

1280×800 및 150~200% 배율에서는 메인 영상의 종횡비를 유지하고 보조 영상 두 개의 최소 가독 크기를 실측한다. 겹침으로 핵심 정보 접근이 불가능하면 우측 고정 영역을 확보하거나 아래로 재배치하는 축소 규칙을 사용자와 확인한다. 현재 HTML은 데스크톱 우측 밀착 배치와 좁은 화면 아래 재배치 초안이다.

## v0.6 뷰어 확대 탭 · 송출 버전 회전 다이얼

사용자 추가 요청: 기존 3화면을 기본으로 유지하고 전체/메인/2번 카메라/3번 카메라 탭에서 선택한 영상을 단독으로 확대해 본다. 메인=링크, 2번=그리퍼, 3번=고정 영상이라는 현재 시안 대응을 따른다. 전체로 돌아오면 메인+우측2개 배치를 복원하고 카메라 선택과 송출 버전 선택은 별도 상태로 유지한다.

버전 선택은 원본/OpenCV/좌표값/통합의 회전 다이얼이다. 원본은 raw, OpenCV는 현재 검출기를 OpenCV로 가정한 detect 시안, 좌표값은 center에 대응한다. 실제 운영 검출기가 AI면 OpenCV라는 이름을 그대로 사용하지 않도록 후속 계약에서 확인한다. 통합은 로컬 목업의 통합 표시 예시이며 서버에 새 view 코드를 추가하거나 검출/보정을 수행하지 않는다.
