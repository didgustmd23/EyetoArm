# C 담당 협업 요청 초안 (A·B·D)

문서 버전 0.1 · C 작성 제안 · 2026-11-13 · 미발송

**목적:** C가 A·B·D에 요청할 추가 협업과 산출물·희망 시점을 정리합니다. A·B의 기존 요청에 대한 C의 회신 자체는 반복하지 않습니다. 이 문서는 초안이며, 기한은 팀 합의 전 제안입니다.

## 1. 공통 전제

- 정상 분류는 벨트를 멈추지 않고 움직이는 부품을 집는 방식입니다.
- 비상·이상 정지 뒤 재시작하는 경우에만 정지 전 목표를 폐기하고 새 프레임으로 다시 처리합니다. 정지 후 재시작 절차는 기존 A 협업요청서 C-07의 의미를 이에 맞춰 정리합니다.
- 현재 모델·launch 설정에는 링크 카메라와 그리퍼 카메라의 센서·ROS 브리지 설정이 있습니다. 실제 실행 중 영상, `CameraInfo.header.frame_id`, TF 및 촬영 시각 일치는 별도 런타임 검증이 필요합니다.
- 현재 모델 설정 기준 링크 카메라는 `upper_arm_link`에, 그리퍼 카메라는 `robotiq_85_base_link`에 장착되어 있습니다. 앞서 제안된 `base_link` 장착과 다르므로 좌표 변환에는 실제 프레임을 사용합니다.
- 카메라·영상 표시 경로는 명령·상태 TCP와 별도입니다. C가 A·B의 표시 입력을 받아 D에 전달하는 경로의 전송 방식·메시지 형식은 미정입니다.
- 일정 제안: 11/22 통합 후보 고정, 11/23~25 최종 테스트 및 발표 준비.

## 2. A에게 요청 (C → A)

### CA-01 카메라 런타임 확인

- **배경:** 모델·launch 설정에는 링크·그리퍼 카메라와 ROS 브리지가 있으나 실제 실행 중 발행과 TF 일치는 아직 확인되지 않았습니다.
- **요청:** C와 함께 링크·그리퍼 영상 및 CameraInfo 발행, `header.frame_id`, `/clock`의 `SIM_TIME`, 촬영 시각 기준 TF 조회를 확인해 주세요.
- **현재 코드 설정:** 링크 카메라 프레임 `link_cam_link` / `link_cam_optical_frame`, 장착 부모 `upper_arm_link`, 토픽 `/link_cam/image`·`/link_cam/camera_info`. 그리퍼 카메라 프레임 `gripper_cam_link` / `gripper_cam_optical_frame`, 장착 부모 `robotiq_85_base_link`, 토픽 `/gripper_cam/image`·`/gripper_cam/depth_image`·`/gripper_cam/camera_info`.
- **산출물:** 실제 발행 토픽, 메시지 헤더 프레임, TF 조회 결과와 미일치 항목.
- **희망 시점:** 11/17 이후, 통합시험 전.

### CA-02 비상·이상 정지 후 재시작 입력 처리

- **배경:** 정상 집기는 이동 중인 벨트에서 수행합니다. 정지 후 재검출은 정상 사이클의 매 집기 절차가 아니라 비상·이상 정지 후 재시작할 때만 필요합니다.
- **요청:** C가 재시작 확인 시각을 `SIM_TIME`으로 전달하면, 정지 전에 받은 목표·관측값은 폐기하고 재시작 뒤 촬영된 새 프레임부터 처리하는 절차를 A와 확인하고 싶습니다.
- **산출물:** 재시작 이벤트 이후 유효한 프레임 판정 규칙 및 시각·세대 대응.
- **희망 시점:** 11/18.

### CA-03 C→D 영상 표시 입력

- **배경:** C가 A의 링크 원본·검출 주석 영상 및 결과·무효화 정보를 받아 D에 중계해야 합니다.
- **요청:** 해당 ROS 토픽 이름·자료형·QoS, 프레임 시각 키와 주석 영상 발행 상태를 공유해 주세요.
- **산출물:** C가 구독할 입력 토픽·메시지 계약.
- **희망 시점:** 11/20 첫 표시 경로 통합 전.

## 3. B에게 요청 (C → B)

### CB-01 실제 카메라 프레임의 좌표 설정 반영

- **배경:** 현재 링크 카메라는 `base_link`가 아니라 움직이는 `upper_arm_link`에 장착되어 있습니다.
- **요청:** B 좌표 계산에서 이미지 촬영 시각 기준 `upper_arm_link` → `link_cam_optical_frame` TF를 사용하고, 카메라가 팔과 함께 움직이는 설정을 반영해 주세요. 실제 `CameraInfo.header.frame_id`는 런타임 확인 결과와 일치시킵니다.
- **산출물:** 사용 프레임·TF 방향·시간 기준이 기록된 B 변환 설정 및 시험값.
- **희망 시점:** 11/17 이후, 목표 인터페이스 통합 전.

### CB-02 로봇·파지 좌표 통합 시험

- **배경:** C는 `base_link`와 `tool0`를 로봇 기준으로 사용하며, 그리퍼 파지 중심은 `tool0`와 다릅니다. C가 MoveIt IK·경로 계획·실행을 담당합니다.
- **요청:** B가 전달하는 파지 목표·목적지 좌표의 기준 프레임과 C가 적용할 그리퍼 오프셋을 맞춘 뒤 알려진 시험값으로 변환 결과를 공동 확인하고 싶습니다.
- **산출물:** 파지 중심 변환과 배출 목표를 포함하는 단위 시험값·기대 결과.
- **희망 시점:** 11/20 첫 A→B→C 통합 전.

## 4. D에게 요청 (C → D)

### CD-01 영상 표시 경로 수신 계약

- **배경:** C→D 영상·결과 표시 경로는 명령·상태 TCP와 분리되며, 전송 방식·포트·직렬화·재접속 규칙이 미정입니다.
- **요청:** D GUI에서 링크 `raw`·`detect`·`center` 중 선택 표시, 그리퍼 영상, 관전 영상 및 결과·무효화 정보를 받기 위한 연결 방식·자료형·채널 선택 규칙을 협의하고 싶습니다.
- **추가 확인:** `overview_cam/image`는 Gazebo 토픽 설정은 있으나 현재 `sim_sort_cell.launch.py`의 ROS 브리지 항목에는 없습니다. D 화면에 관전 영상이 필요한지 확인해 주세요. 필요하면 C가 브리지 범위를 정리합니다.
- **산출물:** 수신 메시지·채널 선택·프레임 시각·단절/재접속 계약.
- **희망 시점:** 11/20 첫 표시 경로 통합 전.

### CD-02 TCP 분류 상태 통합 시험

- **배경:** D GUI와 C 서버 간 분류 명령·상태 통합시험을 준비해야 합니다. 추가 명령 형식은 승인 전 제안으로 관리합니다.
- **요청:** D 클라이언트에서 확인할 요청·응답·오류 상태와 시험 절차를 C 서버 구현과 대조하고, 정상·중복·취소·단절·재접속 시험을 함께 준비하고 싶습니다.
- **산출물:** 시험 메시지·기대 상태·클라이언트 실행 절차와 결과 기록 형식.
- **희망 시점:** 시험 시작 전 계약 확인, 11/23~25 실행.
