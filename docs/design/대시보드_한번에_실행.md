# 대시보드 한 번에 실행

| 버전 | 날짜 | 작성 | 내용 |
|---|---|---|---|
| 0.1 | 2026-11-20 | B담당 | 처음 작성. `dashboard_up.sh`·`dashboard_stack.launch.py` |

Gazebo, C TCP 서버, C 영상 중계기, Windows D 대시보드(+ 선택: A 실시간 YOLO)를 명령 한 줄로 켭니다.
따로 켜는 방법과 각 프로세스 설명은 [서버-대시보드 실행](서버-대시보드%20실행.md)을 봅니다. 켜는 순서는 그 문서와 같습니다.

## 1. 처음 한 번만 준비

| 할 일 | 명령 | 이유 |
|---|---|---|
| ROS 도메인 고정 | `echo 'export ROS_DOMAIN_ID=<팀 번호>' >> ~/.bashrc && source ~/.bashrc` | 모든 터미널이 같은 번호여야 영상·명령이 보입니다 |
| C 패키지 빌드 | `cd ~/EyetoArm/robot_ws && source /opt/ros/jazzy/setup.bash && colcon build --packages-select robot_server_package` | 설치본은 복사본입니다. **C 코드가 바뀔 때마다** 다시 빌드합니다 |
| Windows 저장소 최신화 | (PowerShell) 내 저장소 폴더에서 `git pull` | D 대시보드는 Windows 쪽 코드로 실행됩니다 |
| (YOLO를 쓸 때만) `.venv-a` | `cd ~/EyetoArm && python3 -m venv --system-site-packages .venv-a && .venv-a/bin/pip install -r requirements.txt` | A YOLO 실행 환경 |
| (선택) 짧은 이름 | `echo 'alias eyetoarm-up="$HOME/EyetoArm/scripts/dashboard_up.sh"' >> ~/.bashrc` | 다음부터 `eyetoarm-up`만 입력 |

## 2. 실행 (어느 폴더에서나)

```bash
~/EyetoArm/scripts/dashboard_up.sh                 # Gazebo + C 서버 + 중계기 + Windows 대시보드
~/EyetoArm/scripts/dashboard_up.sh yolo:=true      # + A 실시간 YOLO 검출 영상(detect)
```

옵션 (여러 개를 같이 써도 됩니다)

| 옵션 | 기본값 | 뜻 |
|---|---|---|
| `world:=<sdf 경로>` | `simulation/worlds/sort_cell.sdf` | 다른 월드. 예: `world:=$HOME/EyetoArm/simulation/worlds/single_bolt.sdf` |
| `gui:=false` | `true` | Gazebo 창 없이(저사양 PC) |
| `dashboard:=false` | `true` | Windows 대시보드를 켜지 않음(PowerShell에서 따로 켤 때) |
| `yolo:=true` | `false` | A 실시간 YOLO 검출을 같이 켬. 기록: `outputs/live/detect_<시각>.jsonl` |
| `relay_delay_s:=15` | `8.0` | 중계기·대시보드·YOLO를 켜기 전에 기다리는 시간(초) |
| `run_mode:=multi` | `single` | 남은 Gazebo 처리. `single`은 같은 `ROS_DOMAIN_ID`·`GZ_PARTITION`에 이전 실행에서 남은 Gazebo·노드를 정리(SIGINT → 10초 → SIGTERM → 5초 → SIGKILL)한 뒤 시작하고, 기본 포트(47090·47092·47093)를 다른 프로세스가 쓰면 시작하지 않습니다. `multi`는 경고만 하고 시작합니다. 다른 도메인·파티션의 실행은 건드리지 않습니다 |

끄기: 실행한 터미널에서 `Ctrl+C` 한 번(WSL 쪽 전부). `kill`이나 터미널 창 닫기로 꺼도 이 실행이 띄운 WSL 프로세스는 정리됩니다(기록 `logs/dashboard_stack_guard_<시각>.log`). Windows 대시보드 창은 따로 닫습니다.

## 3. 정상일 때 보이는 것

1. `[dashboard_up] 저장소=... ROS_DOMAIN_ID=<번호>` ← 번호가 팀 번호인지 확인
2. `TCP server listening at [('127.0.0.1', 47090)]`
3. Gazebo 창
4. 약 8초 뒤 `[C video FPS] link:rx=...,tx=...`가 1초마다 나옴
5. `[대시보드] 자동으로 찾음: C:\...\dashboard-client` (두 번째부터는 `지난번 찾은 폴더 사용`) → Windows 창이 뜸
6. (`yolo:=true`) `[YOLO] 기록: ...` → 대시보드 「detect」에서 YOLO 윤곽 영상

### 대시보드 폴더 자동 찾기

런치가 Windows 쪽 `dashboard-client` 폴더를 스스로 찾습니다. 순서:

1. 환경 변수 `EYETOARM_DASHBOARD_DIR`가 있으면 그 폴더
2. 지난번 찾은 폴더(`~/.cache/eyetoarm/dashboard_dir`)가 아직 있으면 그 폴더
3. 없으면 모든 Windows 드라이브를 5단계 깊이까지 검색. `.venv\Scripts\Activate.ps1`과 `src\eyetoarm\gui\window.py`가 **둘 다 있는** 폴더만 고르고, 여러 개면 가장 최근 것

첫 검색은 수십 초 걸릴 수 있습니다(B담당 PC 측정 25.8초). 그 뒤로는 바로 켜집니다.

## 4. 오류가 날 때

| 증상 | 원인 | 해결 |
|---|---|---|
| `ValueError: 'scripts/dashboard_stack.launch.py' is not a valid package name` | `ros2 launch scripts/...`를 저장소 맨 위 폴더가 아닌 곳에서 실행. 파일을 못 찾으면 ros2가 그 글자를 패키지 이름으로 봄 | `~/EyetoArm/scripts/dashboard_up.sh`를 쓰거나 `ros2 launch ~/EyetoArm/scripts/dashboard_stack.launch.py` (전체 경로) |
| `tcp_server`·`display_relay`가 켜지자마자 꺼짐. 47090/47092 관련 오류 (문구는 B담당 미확인) | 이미 다른 터미널에서 켜 둔 서버·중계기·Gazebo가 있음 | `pgrep -af "tcp_server\|display_relay\|gz sim"`으로 확인 → 그 터미널에서 `Ctrl+C` 후 다시 실행 |
| `rx=0.0`이 계속 | ① 터미널마다 `ROS_DOMAIN_ID`가 다름 ② Gazebo가 늦게 뜸 | ① 3절 1번 줄의 번호 확인 ② `relay_delay_s:=15` |
| `rx`는 있는데 `tx=0.0` | 대시보드가 아직 접속하지 않음. 중계기는 대시보드가 붙은 뒤에만 보냄(정상) | 대시보드가 뜨고 `[C 영상] D 접속` 줄이 나온 뒤 `tx`가 오르는지 확인 |
| `[대시보드] dashboard-client(.venv 포함)를 못 찾음` | 폴더가 6단계 이상 깊음, 또는 `.venv`가 없음 | `export EYETOARM_DASHBOARD_DIR='C:\...\dashboard-client'` 후 다시 실행. `.venv`가 없으면 [Dashboard-README](../../dashboard-client/README.md)대로 만들기 |
| 폴더를 옮긴 뒤 대시보드가 안 뜸 | 기억해 둔 주소가 옛 주소 | 다시 실행하면 자동으로 새로 찾음. 안 되면 `rm ~/.cache/eyetoarm/dashboard_dir`. Windows `.venv`는 옮겨도 `Activate.ps1`로 켜집니다(B담당 확인) |
| Windows 창이 안 뜨거나 PowerShell 오류 | WSL→Windows 실행 실패 | `dashboard:=false`로 켜고 PowerShell에서 [서버-대시보드 실행](서버-대시보드%20실행.md) §4대로 따로 실행 |
| 대시보드에 detect/center 버튼 동작이 예전 그대로 | Windows 쪽 저장소가 오래됨 | Windows 저장소 폴더에서 `git pull` |
| C 코드를 받았는데 중계기가 예전처럼 동작 | 빌드 안 함(설치본은 복사본) | 1절 표의 C 패키지 빌드 |
| `[YOLO] ... .venv-a/bin/python 없음 → 생략` | `.venv-a` 없음 | 1절 표의 `.venv-a` 만들기 |
| 「center」 영상이 비어 있음 | 아직 연결 전(정상). B 발행기는 준비, C 중계기 구독·A 실시간 경로 연결이 남음 | — |

## 5. 관련 파일

- `scripts/dashboard_up.sh` — ROS 환경을 불러오고 런치를 실행(저장소 위치를 파일 위치로 찾음)
- `scripts/dashboard_stack.launch.py` — 실제 런치. 서버·중계기는 `ros2 run`으로 부름(`Node`는 `--ros-args`를 붙이는데 두 프로그램이 이를 거부함)
- `scripts/sim_sort_cell.launch.py` — 안에서 불러오는 Gazebo 런치(대용량 영상 DDS 설정 포함)
