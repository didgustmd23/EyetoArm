문서 버전 0.1(검토 반영) · **A 제안 · B 미회신, D는 A 제안 수락(사용자 전달, 원문 미확인) · 최소형 구현됨** · 2026-11-10, 상태 갱신 2026-11-11, 2026-11-12(§8 B 결과 단위 행: 삭제된 협업 요청 참조 정리)

| 대상 | A·B·D가 함께 쓰는 앱 내부 자료형과 그 변경 절차 |
| 배치 | `src/eyetoarm/common/types.py` — **작성됨(2026-11-11).** 최소형 `TimestampBase`·`InputStatus`·`FramePacket`(§3.2, 14개 필드)·`InputStatusEvent`(§3.6, 5개 필드)만 구현. `src/eyetoarm/inputs/base.py`가 상속해 A 확장(`source_ref`·`source_index`)을 붙임. 관측·결과·사건형(§3.3~§3.5)은 미구현 |

이 문서는 A가 먼저 내놓는 **초안**입니다. 자료형·필드 이름, Python 타입, 전달 방식은 모두 제안이며 B·D가 확인하기 전에는 확정이 아닙니다. 이 문서 작성으로 코드·시험·TCP·설정을 바꾸지 않았습니다.

## 1. 목적과 범위

- 목적: A의 프레임·픽셀 관측, B의 작업 좌표·규격 결과, D의 표시·전달이 같은 의미의 필드를 쓰게 하고, 바꿀 때 영향받는 담당이 함께 확인하게 합니다.
- 공통 자료형은 **앱 내부 계약**입니다. TCP 1.1 필드 추가나 스키마 변경이 아닙니다. TCP로 나가는 값은 기존 TCP 명세서 §4 규칙(정수 필드, 식별 문자열 규칙, `timestamp_base` 값 등)을 따릅니다.
- 범위: 1~3주차 분류의 평면 경로. 후속 6D(`PoseObservation`)와 4~5주차 사람 자세 자료형은 실제 착수할 때 확장하며 이 초안에 구현을 끌어오지 않습니다.
- 로봇 명령·실행 슬롯·TCP 명세 개정 제안(분류 명령) 자료형은 C·D 소유이므로 이 A 초안에 넣지 않습니다([C 상세설계 §16.8](C담당_로봇서버_상세설계.md)).

## 2. 관리·검토 역할 (제안)

| 담당 | 초안·소유 제안 | 확인 |
|---|---|---|
| A | `FramePacket`, `PlanarObservation`, `CandidateInvalidationEvent`(가칭), `InputStatusEvent`(가칭) 초안 | B: 픽셀 기준·관측면 필드, D: 전달·버퍼 |
| B | `WorkPlanarResult`(B 상세설계 §7.3 이름, 가칭 유지)의 필드·단위·판정 사유 | A: 원본 관측 식별자 복사, D: 표시·mm 변환 |
| D | GUI 전달 방식·버퍼 수명·클라이언트 API 초안 | A·B: 자료형 소비 방식 |
| C | 이 초안의 소유 대상 없음. 실행 관리자·서버 자료형은 C 소유 그대로 | — |

공통 파일 `common/types.py`는 이 초안 §3의 최소형으로 이미 작성돼 A 입력 모듈이 쓰고 있습니다(사용자 지시 2026-11-11: 초안 기준으로 진행). 기존 최소형은 다시 승인 대기로 돌리지 않고, 이후 변경과 미구현 자료형 추가는 §6 변경 관리 절차를 따릅니다. 파일 관리·변경 반영·호환성 확인은 **A**입니다(사용자 결정 2026-11-11, 프로젝트 계획 §3 공통 파일 소유자 표). 공통 파일을 A가 관리한다고 B 계산이나 D GUI 내부 결함까지 A 책임이 되지는 않습니다.

**역할 구분(사용자 결정 2026-11-11).** 필드 생산자: A(`FramePacket`·`InputStatusEvent`·A 관측형), B(결과형 — 의미·단위·유효 조건 정의). 소비자: B·D(및 B→C goal의 근거 필드를 통해 C), D는 표시·소비 호환 확인. 변경 확인자: 해당 필드의 영향 담당(§6). 파일 관리·반영: A. 이미 작성한 최소형의 사용을 다시 승인 대기로 돌리지 않습니다.

## 3. 자료형별 필드 (제안)

표기: **필수** = 항상 값 있음, **조건부** = 표기한 조건에서만 값, **None 허용** = 값이 없을 수 있음. 타입은 Python 표기 제안입니다.

- 처리 예외·중단·세대 변경 폐기는 `PlanarObservation`을 만들지 않습니다(§3.5·§3.6).

### 3.4 `WorkPlanarResult` (B 소유 제안, B §7.3 기준)

B §5.5에 따라 **B 결과 자료형의 위치·치수는 m**이며, 표시·TCP 경계의 mm 변환은 D가 한 번만 합니다.

| 필드 | 제안 타입 | 단위 | 필수 여부 | 의미 |
|---|---|---|---|---|
| 원본 관측 식별자(`run_id`·`source_id`·`image_seq`·`capture_generation`·`generation`·`job_seq`·`detector_config_id`) | 3.3과 같음 | — | 필수 | A 관측에서 복사. B가 새로 만들지 않음 |
| `calibration_id` | `str \| None` | — | 조건부(`valid = True`면 필수) | 사용한 프로파일. 프로파일 없음으로 거부한 결과에서만 None |
| `transform_config_id` | `str \| None` | — | 조건부(`valid = True`면 필수) | B가 쓴 작업 좌표·로봇 변환 설정 식별자(예: `config/robot/frames.yaml`의 버전·해시. 이름 제안) |
| `center_w_m` | `tuple[float, float] \| None` | m | 조건부(`valid = True`면 필수) | W 기준 중심 |
| `theta_deg` | `float \| None` | 도 | 조건부(볼트이고 `valid = True`면 필수) | 장축각 `0 ≤ θ < 180`. 너트는 None |
| `theta_valid` | `bool` | — | 필수 | 볼트 유효 결과에서 True, 너트는 False(B §7.2 제안 이름) |
| `spec` | 문자열 `"BOLT_A"`·`"BOLT_B"`·`"NUT"`·`"UNRESOLVED"` | — | 필수 | 규격 판정. 판정 불가면 `UNRESOLVED` |
| `measured_length_m` | `float \| None` | m | 조건부(볼트이고 `valid = True`면 필수) | 길이 판정 근거. 기준점(머리 포함/축)은 미결 |
| `aspect_ratio` | `float \| None` | — | 조건부(볼트 판정 시) | 장변/단변. 너트는 None |
| `area_w_m2` | `float \| None` | m² | None 허용 | 면적 건전성 검사 값(B §7.2) |
| `valid` | `bool` | — | 필수 | B 판정 유효 여부 |
| `reason` | `str \| None` | — | 조건부(`valid = False`면 필수) | 무효 사유(예: `DIRECTION_UNSTABLE`, `WORK_COORD_INVALID`) |
| `reason_owner` | 문자열 `"A"`·`"B"` \| None | — | 조건부(`valid = False`면 필수) | 사유 판정 주체 |
| `compute_ms` | `float` | ms | 필수 | B 계산 시간 |

**유효 조건.** `valid = True`이면 `calibration_id`·`transform_config_id`·`center_w_m`이 None이 아니고 `spec`이 `UNRESOLVED`가 아닙니다. `spec`이 `BOLT_A`·`BOLT_B`이면 `theta_deg`·`measured_length_m`이 None이 아니고 `theta_valid = True`입니다. `spec = "NUT"`이면 `theta_deg = None`, `theta_valid = False`입니다. 프로파일이 없는 입력(`calibration_id = None`)은 `valid = False`, `reason = "CALIBRATION_MISMATCH"`, `reason_owner = "A"`로 돌려줍니다(A §5.4: 프로파일 없음 포함).

B §7.3의 `contour_w_m`·`axis_overlay_px`와 파지점·개구폭·목적지(B 상세설계 §15.2)는 이번 최소 초안에서 제외했습니다. 확정 시 타입·단위를 정해 추가합니다.

입력 상태는 프레임이 없는 사건이므로 `image_seq`를 두지 않습니다. 검출 무효(`PlanarObservation.valid = False`)와 섞지 않고, 오류로 완성된 관측을 위조하지 않습니다.

## 4. 불변조건

1. 같은 `run_id` 안에서 `image_seq`는 단조 증가하며 재접속·탐색(seek)·ROS 시간 되감기로 초기화하지 않습니다(세대 증가로 구분).
2. 같은 프레임을 다시 처리해도 원본 ID·원본 시각·수신 시각·`capture_generation`은 그대로이고 `generation`·`job_seq`만 새로 받습니다.
3. `timestamp_base == "PC_RECEIVE"`이면 `timestamp_ms == received_monotonic_ns // 1_000_000`(같은 읽기 값에서 계산).
4. 서로 다른 시간 기준의 시각을 직접 빼지 않습니다.
5. 수신 세대와 처리 세대를 구분하고, 무효화 적용 순서(A §5.4 규칙 1~5, `job_seq` 기준)를 유지합니다.
6. 프레임 없는 로딩 오류에는 프레임 식별자를 None으로 둡니다.
7. 프로파일이 없으면 픽셀 관측까지만 만들고 B 결과를 유효로 만들지 않습니다.
8. `numpy` 배열은 바뀔 수 있는 객체이므로, 처리 중 프레임 버퍼를 다른 쪽이 덮어쓰지 않게 합니다. `flags.writeable = False`는 그 배열(뷰) 객체를 통한 쓰기만 막을 뿐, 같은 메모리를 가리키는 다른 별칭이나 생산자의 버퍼 재사용까지 막지는 못합니다. 따라서 제안은 다음과 같습니다: ① 생산자(입력 어댑터)는 넘긴 버퍼를 다시 쓰지 않는다(재사용 금지) ② 넘길 때 소유권을 소비자에게 양도하거나, 양도할 수 없으면 독립 복사본을 넘긴다 ③ 넘긴 배열은 읽기 전용으로 표시해 실수로 쓰는 것을 막는다(보조 수단) ④ 소비자가 수정하려면 복사한다. 이 중 어느 정책(양도/복사)을 쓸지는 D와 합의 전입니다.
9. GUI 객체 갱신은 GUI 스레드에서만 합니다(A §3, D §A.4).

## 5. 적용 경계

- 유지되는 사용자 확정: 최종 부품 M6×12·M6×40 볼트와 M6 너트, AI 후보 비교 선정(2클래스안은 아직 제안), 스마트폰 실사용 4~5주차, C 월드 녹화는 월드 완료 후.
- 로봇 명령 자료형·실행 슬롯·TCP 명세 개정 제안(분류 명령)은 이 초안에 넣지 않습니다(C·D 소유).

## 6. 변경 관리 절차 (제안)

1. 변경 제안: 의미, 영향 받는 생산자·소비자, 관련 문서 절, 단위, 기존 자료·로그 영향을 적어 제시
2. 관련 담당 확인
3. 영향 담당 확인 뒤 파일 관리 담당 A가 공통 파일과 문서에 반영(B 결과형의 의미·단위·유효 조건은 B 정의를 따름)
4. 단위 시험과 연결 확인(생산→소비 경로)
5. 결정 기록(날짜·확인자·변경 내용)

필수 필드 삭제, 단위 변경, None 허용 규칙 변경은 호환성에 영향이 있는 변경으로 표시하고 소비자 전원의 확인을 받습니다. 별도 버전 관리 시스템이나 레지스트리는 두지 않습니다.

## 7. 설명용 예시 (실제 측정값 아님)

아래 값은 연결을 설명하기 위해 만든 값이며 측정·시험 결과가 아닙니다. 판정 기준값·치수 허용치를 정하지 않습니다.

**예시 1 — 정상 볼트.** `FramePacket(run_id="r1", source_id="gz_cam0", image_seq=120, timestamp_ms=45000, timestamp_base="SIM_TIME", capture_generation=3, …)` → A `PlanarObservation(generation=3, job_seq=57, valid=True, calc_contour=…, observed_face="<합의된 면 ID>", method="opencv")` (관측면이 B와의 파일럿에서 합의됐다고 **가정**한 설명용 값. `top_face`가 확정됐다는 뜻이 아님) → B `WorkPlanarResult(calibration_id="gz_cam0_1280x720_v1", transform_config_id="frames_v1", center_w_m=(0.550, -0.020), theta_deg=12.0, theta_valid=True, spec="BOLT_B", measured_length_m=0.040, valid=True)` → D 표시 `X 550.0 mm, Y -20.0 mm, θ 12.0°`(m→mm 변환은 D가 한 번).

**예시 1-b — 관측면 미확정.** 같은 프레임에서 관측면이 아직 합의되지 않았으면 A `PlanarObservation(observed_face=None, calc_contour=None, valid=False, reason=<관측면 미확정 사유, 이름 미결>)` → B는 유효 결과를 만들지 않음 → D는 이동 후보를 표시하지 않음.

**예시 2 — 너트.** B `WorkPlanarResult(calibration_id="gz_cam0_1280x720_v1", transform_config_id="frames_v1", center_w_m=(0.550, 0.100), spec="NUT", theta_deg=None, theta_valid=False, measured_length_m=None, valid=True)` → D는 중심만 표시하고 θ를 표시하지 않음. TCP `MOVE` 목표로 쓰지 않음.

**예시 3 — 프레임 없는 모델 로드 오류.** `CandidateInvalidationEvent(kind="MODEL_LOAD_FAILED", generation=4, job_seq=None, image_seq=None, …)` → 현재 세대 후보 전체 무효(A §5.4 규칙 3). `PlanarObservation`은 만들지 않음.
