# D 2일차 골격 — 스테이징 기준 아키텍처 반영 현황

갱신: 2026-11-13 · 현재 기준: HEAD ce5531e + D 클라이언트 9개 모듈·시험 1개 index. 원격 fetch/실서버/GUI 실행 없이 코드와 문서만 대조했다.

## 현재 결론

네이티브 세 화면·공통 연결·영상 자리·상태·기록 UI가 구현되어 있다. 준비 조회용 무ID GET_STATUS와 D 임시 Gazebo 표시 경로가 기존 일차 계획보다 먼저 추가되었지만, 정식 표시 연결·로봇 명령·분류 제어·평가/외형 검수 관문은 충족되지 않았다. 아래 R01~R12는 필수 추적 목록으로 유지하며, 자리나 설명이 존재한다는 이유로 해당 요구를 완료 처리하지 않는다.

이 표는 코드 정합 대조이며 GUI 수락시험 결과가 아니다. 창 실행·STATUS 수신·Gazebo 창 캡처의 1회 확인은 [기록검증 「네이티브 실행 확인」](D_2일차_밝은배색_기록검증.md)에 있다. R06/R10 등 자리의 완전성도 실제 데이터·최종 자산 검수가 필요하다.

## 표시 경로와 기존 요구의 경계

window.py 기본은 GzWindowCapture의 Windows Gazebo 창 캡처다. --view camera는 gz_view.py + WSL gz_view_relay.py의 D 임시 127.0.0.1:47091 EAV1/JPEG 중계다. 외형 확인용 /appearance_check/image를 사용하며 A 운영 카메라·C 47090 서버를 바꾸지 않는다. 이 임시 경로는 부록 B의 정식 C 표시 연결이 아니며 그 승인/동기/무효화 시험을 대체하지 않는다. 보조 영상은 아직 자리다.

현재 raw/detect/center는 비활성 표시다. HTML의 OpenCV/좌표값 대응은 당시 시안 명칭이며 실제 검출 모델이나 변환 결과를 증명하지 않는다. 2·3번 단독뷰/통합 다이얼·CSV/스낵바 구현 완료로 표현하지 않는다.

## 검증·승인·후속

직전 검토의 6개 단위시험은 파서/설정/테마 범위이고, 이번에는 문서만 갱신한다. 실제 GUI·C TCP·영상·Gazebo·CSV·성능을 실행하지 않았다. 3~9일차 원래 수락조건과 A/B/C 책임을 유지한다. 실행·모듈·시각 기준은 [골격 v0.9](../design/D_2일차_대시보드_골격.md), 일정 변화는 [9일 계획 갱신 절](../design/D담당_9일_일일계획.md)에 연결한다.

사용자 요청은 미추적 문서4를 최종 index 기준으로 갱신하는 범위다. 기존 구현 승인 근거나 실측 결과를 소급 생성하지 않는다. 소스/시험·권위 설계/명세·index·브랜치·커밋·푸시를 변경하지 않는다. 상시 런타임·서버·브라우저·커널을 생성하지 않으며 기존 Claude/공유 자원은 보존한다.

아래 원격 main=4a43cc9와 blob/동일 트리 확인은 이전 검토 시점의 기록이다. 이번 갱신은 GitHub 최신화 검토가 아니므로 현재 원격 최신이라고 재사용하지 않는다. 이전 HTML 경로는 현재 없으므로 당시 HTML 보완·검증을 현재 산출물로 세지 않는다.

## 결론

9일 계획에는 전체 책임이 대체로 반영되어 있다. 앞서 만든 2일차 골격은 시각 배치 중심이어서 필수 조작·상태·추적·평가의 자리가 구체적이지 않았다. 특히 모든 부품에 집기 흐름을 적용하는 것처럼 보이는 단일 공정선과 분류 STOP/수동 CANCEL을 합친 문구는 수정이 필요했다. 실제 통신을 전부 2일차로 앞당기는 것이 해결책은 아니다. 필수 화면 자리와 모의 수락조건을 지금 고정하고 3~9일차 연결 관문을 유지한다.

## 계약·기준 정합성 주의

- 부록 B는 비어 있지 않다. B.1의 3영상/링크 종류/JSON/명령 TCP와 분리 요구는 사용자 확정이다. B.2~B.9의 WebSocket·포트·헤더·stamp_ns·순서·재접속 규칙은 A 제안이며 C/D 최종 확인 대상이다. '모든 동기 키가 미정'이라고 뭉뚱그리지 않는다.
- 표시 초안의 stamp_ns(SIM_TIME), A 내부 run_id/image_seq/generation/job_seq, C 실행 run_epoch를 같은 식별자로 통합하지 않는다. B 내부 m는 D 표시/TCP 경계에서 한 번만 mm로 변환한다. 영상 확대 픽셀과 검출 좌표 px를 혼동하지 않는다.
- 저장 VIDEO_POS는 표시/오프라인 평가용이며 Gazebo 벨트 연동 분류 입력으로 사용하지 않는 제안 경계를 유지한다. Gazebo SIM_TIME과 PC 단조 수신 중단 감시를 나눈다. PC_RECEIVE를 촬영 시각으로 표시하지 않는다.
- 아키텍처 §4.1 첫 표의 'GUI 모드'는 최신 §2.1의 '운전 모드 없음' 및 D §A.11과 용어 충돌이 있다. 이번 계획은 구체적인 최신 결정에 맞춰 작업 상태/허용 여부로 표현하며 권위 문서를 임의 수정하지 않았다.
- 6D ArUco/PnP는 사용자 확정 후속 범위라 이번 분류 화면의 필수 누락이 아니다. 4종 그리퍼·연속 집기·실물 마찰 파지의 범위 축소는 제안과 확정 수준을 구분한다. 기존 데이터/데모는 보존한다.
- 100회 최초 일치 ACK 목표와 P95≤300ms는 A 시험도구의 정의된 구간 목표다. 300ms를 D의 사용자 실행→ACK나 GUI 화면 반응의 합격값으로 옮기지 않는다. D 구간은 별도 측정·기준 합의가 필요하다.

## 수정 범위·검증·미완료

자체 2일차 골격 MD/HTML의 조작·상태·분기·추적·집계 자리를 보완하고, 9일 계획에 이 대조표의 추가 관문을 연결한다. 원본 아키텍처/A/B/C/D 상세설계·프로토콜·스키마·벡터·제품 소스·시험 코드는 수정하지 않는다. 실제 구현 승인을 소급 생성하지 않는다.

메인 Codex가 원문·원격 commit/blob·동일 트리를 직접 확인했다. architecture_requirements_auditor(gpt-6.1-sol, medium)는 아키텍처/일정, interface_contract_auditor(gpt-6-luna, medium)는 규약/상태를 읽기 전용 검토했고 메인이 주요 근거를 재확인했다. 별도로 기존 Claude 두 세션의 ping/회신도 확인했다. claude-impl·codex-review 모두 실제 CLI claude, 모델 claude-opus-5-5, Hub 설정 medium/idle이며 워커 내부 effort/공식 session_id는 미노출이다. 이번 검토를 Claude가 수행했다고 주장하지 않는다.

이것은 설계 정합성 검토이며 실제 GUI·모션·C TCP·영상·Gazebo·CSV·성능 시험은 실행하지 않았다. 1일차 실제 C 접속 거부 기록도 이번 조회로 해소된 것이 아니다. 후속 완료 관문은 별도 실행 증거가 필요하다.
